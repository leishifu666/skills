# LSF 归藏社交图文技能

## 技能介绍

把已有内容整理成适合小红书、微信公众号和信息流展示的图文卡片。先提炼每页要表达的观点，再用照片、截图、数据或视频支撑内容，最后通过 HTML/CSS 排版并渲染为图片；实况卡片则在同一版式中加入短视频。

适合有内容和素材、需要制作封面或组图的创作者。可输入文章、脚本、产品说明、字幕、照片、应用截图、录屏或短视频。

| 需求 | 交付内容 |
| --- | --- |
| 小红书图文 / 轮播组图 | 封面与内容页，常用 3:4，默认画板为 1080×1440 |
| 微信公众号封面 | 21:9 主封面与 1:1 方形封面，分别构图并提供组合预览 |
| 截图说明 / 产品介绍 / 教程拆页 | 保留截图信息，配合标题、注释与页面层级 |
| Live Photo 实况卡片 | 单视频、二宫格、三宫格、四宫格或三连拼图，交付 JPG、MOV 与 `.pvt` 包 |
| 文章封面 / 平台缩略图 | 按目标比例制作封面，并保留可继续编辑的 HTML |

内置两套视觉系统：**电子杂志风（Editorial）**采用宋体或衬线标题、纸张与墨色、旁注及大图；**瑞士国际主义（Swiss）**采用左对齐网格、细线、字号对比和单一强调色。共提供 28 个版式骨架与 10 套主题预设。根据表达意图选择风格，不按题材固定分配。

可这样调用，按本次需求选择产出：

```text
用 $lsf-guizang-social-card-skill，把这篇文章做成 5 张小红书 3:4 图文，采用瑞士风和 IKB 蓝。
用 $lsf-guizang-social-card-skill，把这篇文章做成公众号 21:9 + 1:1 封面对，采用电子杂志风。
用 $lsf-guizang-social-card-skill，把这三段旅行视频做成三连实况拼图，保留风景，不额外加字。
```

本技能独立维护，借鉴归藏 PPT 风格体系的视觉原则。不得修改原 PPT 技能、模板或参考资料；如已安装原 PPT 技能，只可读取作为参考。

生成产物必须放在任务文件夹内，不得放在技能根目录。默认使用本仓库的 `local-tests/<slug>/`，或用户明确指定的输出目录。不得在 `SKILL.md` 旁创建 `social-card-*`、`livephoto-*`、`wechat-*`、`output/` 等任务目录，也不得散放渲染产物。

## 适用产出与范围

适用于：

- 社交卡片与轮播组图：封面加内容页，尤其是小红书 / Rednote 的 3:4 图文。
- 短时 Live Photo 实况卡片：用户明确需要实况照片，并提供视频证据或录屏。
- 素材优先的实况拼图：用户有高质量视频，需要单视频、二宫格、三宫格或四宫格动态卡片，少加字或不加字。
- 三连实况拼图：用一张卡片呈现三个短视频、三个结果、三个视角，或信息密度较高的对比。
- 长视频转实况卡片前的诊断：先判断截取、倍速、拆成三连拼图，还是请用户指定时间段，再渲染。
- 微信公众号封面对：一个 `21:9` 主封面加一个 `1:1` 方形封面，放在同一 HTML 中检查视觉关系。
- 以截图为主的产品图文、文章封面、教程组图、户外或生活方式笔记、AI 或产品更新说明。
- 需要归藏风瑞士网格或电子杂志版式的社交图片。

不适用于：

- 完整幻灯片或横向 PPT 网站，应使用 PPT 技能。
- 长视频生成，应使用视频技能。本技能只支持受版式约束的短实况卡片，用视频替换静态图片区域。
- 无排版或文章提炼需求的纯图片编辑。

### 小红书品类能力边界

小红书常见的 11 个品类分为三类。具体版式路由见 `references/category-cookbook.md`。

**可完整处理文案、结构与图像叙事：**

- 旅行、职场、推荐（推荐类需明确子类型）。

**可处理文案与结构，图片需由用户或素材库提供：**

- 游戏、影视、美食中的食谱方向、彩妆中的教程方向、健身、家居、穿搭中的精选或专题方向。

**超出范围，接收需求时应说明能力限制：**

- 美食中的菜品大片与摆盘摄影。
- 穿搭中的日常 OOTD 全身照，不能生成或模拟。
- 情感中的梦核或氛围装饰风，与电子杂志和瑞士风均不匹配。
- Y2K、千禧辣妹、哥特萝莉、kawaii 等装饰型审美。
- 以摄影作品本身作为全部交付内容的纯摄影展示。

遇到第三类需求，在设计前说明无法完成的部分，不要套用偏离用户意图的版式。

## 核心原则

先明确表达。目标是把素材转成清晰的视觉论证，而不是把文字塞进海报。

每页先确定：

- 观众一眼应该理解什么？
- 哪张证据图、截图或照片能支撑它？
- 哪些文字需要放大，哪些可成为图注或辅助信息？
- 哪些内容应放在笔记正文，可从图片中删去？

## 工作流程

### 1. 接收需求与素材

只补充会改变结果的缺失信息：

- 目标平台与比例。
- 原始文案、字幕、文章或标题。
- **小红书品类**：若用户指定上述 11 个常见品类，按 `references/category-cookbook.md` 选择版式并确认能力边界。超出范围的部分必须在设计前说明，不擅自套版。
- 用户图片、截图，以及各自应出现的位置。**新闻、教程、数据与测评内容应主动询问是否有截图或照片**，这些是证据层；缺少真实素材的海报容易显得空泛。
- 用户视频素材：制作实况卡片默认使用用户提供的视频；网络免费视频仅用于演示、宣传案例，或用户明确要求寻找素材时。确认目标平台，现有生产规范按小红书 `5s`、微信公众号 `3s` 处理，公众号实况照片需从 iPhone 上传。剪辑前读取 `references/live-photo-production.md`，判断是单视频实况、三连拼图还是长视频接收。素材过长或包含多个可用片段时，先做低成本诊断，再一次性确认截取、倍速、拆成多个视频区域，或用户指定时间段。素材短于目标时长时，询问补充更长片段、接受较短实况，或明确允许停帧 / 慢放。焦点不明确时，提供裁切或放大选项，让用户决定后再执行。
- **用户只提供文字、完全没有图片时，设计前只询问一次：**

  ```text
  这篇需要 1–2 张图，有三种方式：
  A. 使用你提供的照片 / 截图（推荐，更能保留真实内容）
  B. 我去 Pexels / Unsplash / Flickr 找图
  C. 用 AI 生成
  ```

  用一句话推荐 A，说明用户自己的照片有助于减少 AI 感。接受用户的选择，包括“都行，你看着办”，随后继续。**不重复询问，也不在后续多轮持续劝选 A。**
- 已指定的风格：瑞士风、电子杂志风、科技、户外等。
- 硬约束：标题文字、1:1 封面不要图片、必须有硬件照片、截图必须可读等。

已有足够上下文时，按合理假设继续。

涉及当前产品发布、政策、价格、效果声明或新闻时，通过浏览查证可能变化的事实，并在最终回复中注明来源。

### 2. 提炼内容主线

设计前把素材转成页面计划。

小红书图文：

- 第 1 页为封面钩子。
- 第 2–N 页每页只承载一个观点。
- 多数笔记采用 5–9 页；下半页空白过多时压缩或合并页面。
- 细节放在笔记正文，图片负责钩子、对比、清单与结论。

微信公众号封面：

- 成对制作：`21:9` 主封面与 `1:1` 方形封面。
- 两张封面放在同一 HTML 文件，并添加组合预览区域，便于检查视觉关系。
- `21:9` 保留完整或近完整标题、副标题与一个明确的视觉关系。
- `1:1` 从长标题提炼短标题，采用居中的大字，默认不放图片，不堆挤副标题。

### 3. 选择视觉系统

每套图文选择一种风格。**两套系统不绑定具体题材**，区别在表达方式。职场文章可以用电子杂志风，旅行清单也可以用瑞士风；按想表达的感受选择。

**电子杂志 × 电子墨水（Editorial Magazine × E-ink）：**

- 衬线 / 宋体标题，克制的无衬线正文，纸张与墨色配色。
- 暖纸色底上叠加纸纹、墨晕或 WebGL 画布等氛围层。
- 使用清单行、旁注、摘引和大图区域，形成杂志专题的阅读感。
- 适合沉静、有编排感的内容表达。

**瑞士国际主义（Swiss International）：**

- Inter / Helvetica 字体感，大标题使用轻字重，小标签采用等宽字体。
- 严格左对齐网格、发丝线与一种高饱和强调色。
- 使用填色矩阵、KPI 数据塔、横向条形图与编号陈述，突出系统和数据。
- 适合量化、明确、有结构的内容表达。

两种风格都可用时，依据编辑意图判断：更像专题报道，还是产品更新说明？由表达意图决定，不由题材决定。

除非用户明确要求混合，不在同一套图文中混用两套视觉系统。

随后选择一个主题：

- 电子杂志风有 6 套配色：墨水经典（Ink Classic）、靛蓝瓷（Indigo Porcelain）、森林墨（Forest Ink）、牛皮纸（Kraft Paper）、沙丘（Dune）、午夜墨（Midnight Ink）。午夜墨是唯一暗色变体，仅用于游戏主视觉、夜景摄影或电影感封面。
- 瑞士风有 4 套强调色：IKB 蓝（IKB Blue）、柠檬黄（Lemon Yellow）、柠檬绿（Lemon Green）、安全橙（Safety Orange）。

精确 CSS 变量见 `references/theme-presets.md`。除非用户有严格品牌要求，不随意另造配色。

### 4. 规划页面

制定简明内部计划：

```text
第 01 页 / 封面 / 钩子 / 图片来源 / 版式意图
第 02 页 / 观点 / 核心文案 / 视觉证据 / 版式意图
……
```

用户要求确认方案时，在渲染前展示计划；否则作为内部计划使用并继续。

按 `references/layout-recipes.md` 选择页面结构，避免每页重复“标题加卡片”。

制作 3:4 图片时，编码前读取 `references/portrait-fill.md`。短表格或清单要扩展成完整竖版构图，可加入摘引栏、证据图、旁注、更大的行高或背景主视觉区域。

观众可见文案必须描述用户的真实场景，而非制作方法。`3s`、`5s`、`Live Photo`、三连拼图、信息量、长视频接收、倍速、高光检测、单个动作点、版式模板等内部词，可用于规划、文件名、核查记录与交付说明；除非用户在制作这些概念的教程，不得用作 H1、钩子或主要正文。渲染前以观众视角读一遍所有标题，像任务要求的文案应改为具体场景文案。

不得为了满足自动密度警告而添加模板之外的装饰。额外刻度尺、侧栏、伪时间轴、装饰标签或虚构徽章，必须来自既有版式或用户要求。出现密度警告时，选择更合适的版式、调整真实内容尺寸，或说明视觉理由并接受建议性警告；不添加无意义 UI。

实况卡片先按普通社交卡片规划，再明确动态的作用：一个动作点、一个小过程、前后变化、三个并列结果，或氛围 / 证据。结构变化只是一处或多处图片区域改为视频区域。沿用比例、裁切、安全区、字体和风格规则，并把静态图裁切逻辑用于视频。首帧需通过静态图检查：无过度裁切，关键 UI 或内容可读，且符合所选版式。渲染前读取 `references/live-photo-production.md`。

素材优先的实况拼图以视频为主，少加字或不加字：单视频封面一个短标题即可，二宫格、三宫格和四宫格通常不额外加字。单视频叠字时，使用 M16 大图主导封面 / 图片压字规则：先做主体映射，选择安全的安静区域；电子杂志标题用正常至中等字重的衬线 / 宋体、纸白色文字，默认不加全画布遮罩。不得另加引题、元信息、发丝线、标签、刻度、徽章、字幕或制作说明来制造设计感。只有一个标题时，用语义断行、字号、字距、对齐与位置完成排版。素材自带的文字属于视频内容；除非用户要求，避免额外加字。

### 4.5. 复制起始模板

不要从零编写 HTML，按第 3 步的视觉系统复制模板：

- 电子杂志 × 电子墨水 → 将 `assets/template-editorial-card.html` 复制到任务文件夹，命名为 `index.html`。
- 瑞士国际主义 → 将 `assets/template-swiss-card.html` 复制到任务文件夹，命名为 `index.html`。

模板已包含字体加载、主题变量、三种画板尺寸（`.poster.xhs` / `.poster.square` / `.poster.wide`）、封面对预览框、纹理与背景层，以及版式引用的全部类定义。

在 `<html>` 元素上设置主题或强调色，从对应列表中选择一个值：

- 电子杂志：`<html data-theme="ink-classic | indigo-porcelain | forest-ink | kraft-paper | dune | midnight-ink">`。
- 瑞士风：`<html data-accent="ikb | lemon-yellow | lemon-green | safety-orange">`。

将 `<!-- POSTERS_HERE -->` 后的占位海报替换为每页一个 `<section class="poster ...">`，使用所选版式的 HTML 骨架：电子杂志 M01–M16，瑞士风 S01–S12。不要载入另一套模板的类系统：电子杂志版式依赖衬线标题与 ledger / marginalia / pipeline-v；瑞士版式依赖 Inter 与 card-fills / matrix / h-bar / kpi-tower。混用会破坏布局。

### 5. 构建与渲染

默认实现方式：

- 在 `local-tests/<slug>/` 下创建任务文件夹，或使用用户指定的输出目录。不得把任务目录、渲染图片、MOV、`.pvt` 包或下载素材放在技能根目录、`SKILL.md` 旁边。
- 原始图片放在任务内的 `assets/`。
- 从第 4.5 步复制的模板开始，不使用空白文件。页面变化优先限制在 `<!-- POSTERS_HERE -->` 区域。需要自定义 CSS 时，在复制的文件内增加命名明确的任务专用样式块，并重置语义元素默认值，例如 `figure { margin:0; }`，避免浏览器默认间距干扰。
- 使用 Playwright 或浏览器截图工具导出每个 `.poster` 或 `.cover` 节点。
- 渲染图片保存到任务内的 `output/`。
- 核对尺寸并查看渲染后的 PNG。
- 保留自动检查入口 `node validate-social-deck.mjs <task-dir>`。检查溢出（R1）、页脚碰撞（R2）、瑞士大标题粗字重（R3）、最小字号（R4）、四横带密度（R5）、`.h-xl` 行数上限（R6）、浏览器默认 figure 外边距偏移（R7）、视觉边界 / 底部留白（R8）、标题与内容间距（R9）。任一 FAIL 返回退出码 1；用户要求自动检查时，交付前修复。WARN 为建议项，但需阅读。

实况卡片分支：

- 渲染前判断信息量：`3s` 适合一个动作点，`5s` 适合一个小过程，三连拼图适合三个并列片段，不适合复杂叙事；长视频先诊断。
- 长素材不要宣称可精确自动检测高光。先探测时长与分辨率，制作稀疏抽帧联系表，再选择截取、倍速、拆分 / 三连，或请用户指定时间段。
- 从各视频区域提取首帧，放入最终静态卡片版式，在制作 `.pvt` 前展示或检查预览。先排除裁切与层级问题，减少后续渲染成本。
- 按平台目标时长渲染配对 MOV：小红书 `5s`，微信公众号 `3s`。
- 从可读的代表帧提取关键 JPG。
- 使用 `makelive` 将 `JPG + MOV` 打包为 `.pvt`，iPhone 测试时将 `.pvt` 作为一个完整项目通过 AirDrop 传送。
- 检查尺寸、时长、帧数、包内容与动态质量。视觉检查优先使用抽帧联系表，只需查看最终拼接图；具体命令与故障检查见 `references/live-photo-production.md`。

不把操作说明、快捷键或使用解释写进图片。

电子杂志风使用分层背景，优先选择克制的 WebGL 墨流画布，或冻结的程序化画布加纸纹。读取 `references/background-systems.md`；不要只用纯米色底，也不要添加满页网格或点阵背景。

### 6. 图片与截图处理

用户提供截图时：

- 保留截图内容，除非用户要求重新设计。
- 优先用程序化外框：目标比例画布、安全内边距、干净背景和可读截图。
- 不拉伸截图。
- 清晰度重要时，放大截图区域，减少旁边的文字。

#### 图片压字

满铺封面、大图区域或生成图上叠字时，遵循 `references/image-overlay.md`：

- **先选图，必要时才着色。** 照片覆盖画布 ≥60% 时，先通过安静区域和光线检查。先不加遮罩构图；缩略图检查失败时，只在标题附近添加与图像色调一致的局部着色，默认不加全画布渐变遮罩。
- **必须做主体映射。** 放置标题前，用图像读取工具查看图片，用自然语言描述主体面部或焦点特征的位置，并在主视觉块附近用 HTML 注释记录主体映射。文字只能放在已记录的安全区域。
- **每张照片内联设置 `object-position`。** 模板默认值 `center 50%` 仅为兜底，不代表推荐值。每个 `<img>` 都要根据主体位置设置，例如中段主体使用 `style="object-position:center 62%"`，天空占比较大且主体在地平线的风景使用 `center 30%`，前景装备使用 `center 70%`。范围见 `references/components.md`，人脸照片规则见 `image-overlay.md`。跳过此步会在 `r-3x4`、`r-21x9` 等比例中裁掉主体。
- **缩略图检查。** 将渲染后的 PNG 缩到 360 px 宽，确认标题仍可读。文字与照片争夺注意力时，移动标题、换图或加局部着色；照片显得失去层次时，说明着色过重，或该图不适合压字。

电子杂志暗色封面（如游戏主视觉上的日志封面）和瑞士大图封面都需这些检查。省略检查是已知失败模式，见 `style-system.md` 反例 D。

用户没有图片时：

- 只有第 1 步的三选一选择 B（网络找图）或 C（AI 生成），才进入此分支。不得未经选择直接使用 B 或 C。
- C（AI 生成）：只在确有价值的页面使用生成位图，通常 1–2 页。图片应符合页面的视觉作用，不作为通用装饰。除非明确需要，不在生成图片中嵌入标题、页码、Logo 或虚假 UI 标签。
- B（网络找图）：按下一节处理。

#### 网络素材图片

用户没有截图 / 照片，且生成位图不适合页面用途时，例如杂志氛围图、户外或生活方式背景、游戏封面图、真实产品图，可从网络取图补充内容。

现有素材流程为：**先获取、后说明来源，由用户决定署名方式。** 不根据猜测的许可条件预先筛掉来源；最终合成作品的使用者决定素材是否可用。

按需选择以下来源。现有流程使用这些提供免费内容的图库，不从视觉中国、Getty、站酷海洛等付费图库取图；具体图片许可仍需逐项核对。

1. **Unsplash**：`https://unsplash.com/s/photos/<keyword>`。适合户外、生活方式与氛围背景，英文关键词效果较好，许可按具体素材核对。
2. **Pexels**：`https://www.pexels.com/search/<keyword>/` 或 `https://www.pexels.com/zh-cn/search/<keyword>/`。支持中文关键词，可补充中文街景、国风物件、本地地名等国内场景。中国相关题材或中文关键词优先使用，素材适用 Pexels License。
3. **Flickr 的 CC 许可素材池**：`https://www.flickr.com/search/?text=<keyword>&license=2%2C3%2C4%2C5%2C6%2C9`。`license=2,3,4,5,6,9` 限定 Creative Commons 照片，适合街拍、场景中的人物、真实室内等纪实素材。用户选择标注来源时保留 CC 署名。
4. **Wallhaven**：`https://wallhaven.cc/search?q=<keyword>`。适合游戏、动漫与壁纸题材，内容由用户上传，权利归属未经核实。
5. **直接网络搜索**：需要特定产品渲染、游戏画面或历史照片时，使用 WebFetch / WebSearch 寻找候选 URL。

电子杂志风的选图顺序：**Pexels（中文关键词或中国场景）→ Unsplash → Flickr CC（需要真实生活感时）→ 直接搜索**。瑞士风较少使用图库；产品渲染、UI 截图或 KeyShot 风格图片宜由用户提供或 AI 生成。

获取方式：

- 用 WebFetch 或 `curl` 下载到任务文件夹的 `assets/`。
- 按用途命名，不用哈希名，例如 `assets/hero-mountain.jpg`、`assets/ui-pulse-card.png`。
- 在 `assets/SOURCES.md` 逐行记录文件与来源：`hero-mountain.jpg ← <url>`。即使最终图片不署名，也要保留来源记录。

取图后，在定稿前向用户说明来源：

```text
我从 <site> 获取了这些图：
- assets/hero-mountain.jpg — <url>
- assets/ui-pulse-card.png — <url>

版权未经核实，请判断是否可用。
是否需要在图文中标注来源？
- 要：将“Photo · <site> · @<author>”加到对应页脚或角标。
- 不要：原样使用，不加注释。
```

用户选择标注时，加小型等宽图注：瑞士风使用角落 `.t-meta`、18–20px；电子杂志风在图片区域旁使用 `.label`。不要挤占视觉焦点。

用户选择不标注时，继续执行；来源仍保存在 `assets/SOURCES.md`。

图片只是合成图中的一个元素时，例如九图矩阵中的一张，不要强加会破坏布局的署名标签。

### 7. 交付

**先展示结果，按请求自动检查。** 每次渲染后自动跑校验会延迟用户查看，默认流程：

1. 渲染完成后立即用绝对路径内嵌展示图片，并用一句话说明产出。
2. 只询问一次：“先你自己看，还是我先自动核查一遍？”
3. 用户说“我自己看”“先给我”或“不需要”时，停止并等待其反馈。
4. 用户说“你查吧”“自动检查”或同意时，再运行 `node validate-social-deck.mjs <task-dir>`，修复 FAIL 后重新渲染，说明密度或行数上限 WARN。

不要在展示图片前擅自运行校验器；用户往往能更快发现视觉问题。

用户查看或要求自动检查后，最终回复包含：

- 输出目录。
- 有助于查看时，用绝对路径内嵌展示渲染图片。
- 简要说明尺寸与验证情况，或注明“尚未自动检查，等待查看反馈”。
- 网络图片的来源 URL、网站与用户的署名选择。
- 实况卡片的 `.pvt` 包、调试用 `JPG + MOV`、目标平台时长与验证摘要。
- 实况发布提醒：按现有生产规范，小红书 `5s`、微信公众号 `3s`；将 `.pvt` 作为一个完整包通过 AirDrop 传到 iPhone，再从对应移动应用入口发布。桌面 / 网页上传通常无法将 `.pvt` 识别为可发布的实况照片。
- 用户无法使用 iPhone / AirDrop 路径时，例如仅桌面操作、Android 或平台不支持实况照片，提供替代选项：由同一 MOV 导出短循环 GIF 或无声 MP4。它们保留动态内容，但失去实况照片按压播放体验；切换前先确认。
- 未解决的限制，例如源图分辨率不足。

## 必须遵守的约束

- 不修改原归藏 PPT 技能或其他上游技能。
- 不在技能根目录生成作品。任务产物默认位于 `local-tests/<slug>/`，或用户指定的输出目录；禁止根目录任务文件夹与散放输出。
- 不添加随机装饰性 SVG 椭圆、色块、雨滴、贴纸或无意义圆形。
- 不默认使用嵌套卡片或通用 SaaS 卡片布局。
- 文字不得溢出、贴边或碰撞页脚。将 `.foot` 放在 flex 列中，用 `margin-top: auto` 固定到底部，不用 `position: absolute` 覆盖增长中的内容。
- 溢出时先测量：`1-40px` 做微调或收紧，`40-90px` 做局部压缩，`90-160px` 稍压标题或段落；只有 `160px+` 才考虑换版式或删内容。修复后检查 R8 底部留白，避免从溢出变成下半页大片空白。
- 标题不得贴住下一内容块。主标题下方通常至少留 `28px`，局部标题至少留 `16px`；视觉检查前可用 R9 核对。
- 文字必须适合手机阅读。
- 瑞士大标题不内联同时设置 `font-size` 与 `font-weight`，使用 `.h-hero` / `.h-statement` / `.h-xl` / `.num-mega`。80–120px、字重 700–900 的标题不符合瑞士风，遵循“越大越轻”。
- 电子杂志海报不得只有纯纸色底、每行等宽标签而没有氛围层。按 `references/style-system.md` 的电子杂志识别检查执行，仅用衬线标题不足以形成该风格。
- 不编造数据、发布细节或百分比。
- 未经用户明确接受，不裁掉人脸、关键 UI 文字、硬件或产品细节。
- 不将视频卡片做成伪静帧序列而不说明。源素材短于目标时长时，补充长素材、采用平台可接受的短时长，或明确说明停帧 / 慢放。
- 实况卡片不得跳过首帧预览。视频区域仍需遵守静态 3:4 版式与裁切规则，之后再渲染 MOV。
- 不让结果视频在浅裁切窗口中滚动跨越章节边界，以免产生视频重叠感。打包前检查抽帧联系表并选择稳定的时间段。
- 为可读性放大或裁切视频时，不猜测用户的视觉优先级。说明取舍并在用户确认后执行；需求已明确焦点区域时可直接执行。
- 不直接将 21:9 封面裁成 1:1，两个比例分别构图。
- **3:4 卡片内容必须覆盖 ≥75% 画布高度。** 超过画布高度 15% 的纯空白带需有留白理由：主视觉图片本身需要呼吸空间、单句宣言式主标题，或段落前后留白（前后总和 ≤15%）。**禁止用 `<div style="flex: 1"></div>` 从上下挤压内容，使其集中在中段。** 杂志对开页可吸收留白，社交卡片逐张展示，内容不足会像漏排。各版式最低密度见 `references/layout-recipes.md` 的“Minimum density”段；渲染后按 `qa-checklist.md` 做四横带密度检查。
