# Seedance 2.0 提示词工程格式

## 定位

这里定义的是 `Seedance 2.0` 的专业 Prompt 工程规范。
目标不是写一段泛泛的生视频描述，而是把分镜、资产和执行要求整理成可直接生产的视频提示词包。

这个文件同时是：
- 角色资产 agent 的规则库
- 场景资产 agent 的规则库
- 道具资产 agent 的规则库
- Prompt 整合 agent 的规则库
- 质量 gate 的审核基准

## Prompt 工程核心结构

推荐基础结构：

```text
主体 + 动作 + 场景 + 光影 + 镜头语言 + 风格 + 画质 + 一致性约束 + 限制项
```

核心原则：
- 角色层尽量稳定
- 变化主要发生在动作层、场景层和镜头层
- 图负责外观，Prompt 负责动作和镜头
- 角色一致性优先于复杂动作和复杂运镜

## 产物层级规则

### 镜头级 Prompt
- 属于中间工作层
- 允许保留单镜头视角的信息密度
- 不能直接作为最终交付给 `Seedance 2.0`

### 结构化 segment 草稿
- 属于内部整理层
- 允许短暂保留时间拆分与结构标签
- 不能直接作为最终交付态

### 最终单段总 Prompt
- 属于最终交付层
- 必须压成单段、连贯、导演化的总提示词
- 不允许保留说明书标签、字段名、schema 痕迹

## 文生视频写法

适用：
- 没有参考图
- 先快速验证创意方向
- 前期草稿试片

推荐结构：
```text
角色描述 + 场景描述 + 动作描述 + 光影描述 + 镜头语言 + 风格 + 画质 + 约束
```

## 图生视频写法

最稳工作流：
```text
参考图锁定外观 → Prompt 写动作 → Prompt 写镜头 → 最后补约束
```

错误做法：
```text
已经有参考图了，还在 Prompt 里重复写大量外观信息
```

## `@引用素材` 机制

Seedance 2.0 支持通过 `@引用名` 调用上传素材，用于角色一致性、多模态参考和镜头控制。

高可信示例包括：
- `@AssetName`
- `@Image1`
- `@Video1`
- `@Audio1`

其中：
- `@AssetName` 更接近通用引用规则
- `@Image1 / @Video1 / @Audio1` 更接近常见示例命名

关于素材数量上限，当前采用谨慎口径：
- 最多 `9` 张图片
- 最多 `3` 段视频
- 最多 `3` 段音频

不要把这条写死成“总共最多 9 个素材”。

## 真人角色资产提示词结构

如果角色是真人、主持人、记者、同事、领导、老师等人像角色，角色资产提示词必须写成稳定人像参考结构，而不是剧情说明。

推荐模板：
```text
超写实人像角色设定图，@角色名，半身特写，上胸到头部构图，电影级写实摄影质感，RAW质感，8K，高一致性同一人物，角色身份，稳定脸部结构与五官特征，皮肤纹理真实细腻，稳定发型，稳定服装，中性冷灰纯净背景，专业棚拍人像布光，整体高级自然，适合做统一角色资产参考。
```

## 角色一致性三层控制

1. 参考图锚定
2. 文本锚点重复
3. 变化只放在动作和镜头上

推荐角色锚点维度：
- 年龄感
- 发型
- 服装
- 面部结构
- 气质识别点

## 角色漂移修复优先级

当角色漂移时，必须按以下顺序修：
1. 加强参考图锚定与文本锚点
2. 减少动作复杂度
3. 降低镜头复杂度
4. 删掉重复但无帮助的风格词

示例修正：
```text
保持 @Image1 中角色外观、发型、服装、面部结构一致
```

## Seedance 标准骨架

执行场记优先把镜头信息整理到这个骨架里：
- 主体
- 动作
- 场景
- 镜头
- 风格
- 音频
- 对白（有说话时补充）

图生视频场景可进一步压缩为：
- 主体 + 动作
- 背景 + 动作
- 镜头 + 运动

## 镜头级标准格式

每个镜头建议至少包含：
- 主体与动作
- 对白与口播
- 镜头语言
- 视觉氛围
- 音效与配乐
- 情绪与节奏
- 一致性约束
- 避免事项
- Seedance 标准结构拆分
- 短提示词模式
- Seedance 2.0 整合提示词

## 对白格式

推荐：
```text
小慧："你说，你什么办法，可以让我早一点放假？" 语气机灵试探，口型同步。
小央："这个……不好吧。" 语气迟疑克制，轻微停顿，口型同步。
无对白，以环境音和配乐推进。
```

规则：
- 可说出的内容统一使用英文双引号 `""`
- `无对白` 类描述不加引号

## 多镜头写法

一个 `5-15s` 视频建议先从 `2-4` 个镜头做起。

推荐结构：
```text
镜头1：建立主体和环境
镜头2：推进动作 / 情绪
镜头3：完成收束 / 转折
统一要求：角色一致、服装一致、面部稳定、动作自然、场景连续、不要字幕、不要水印
```

## 广告短片 Prompt 结构

推荐结构：
```text
主体/产品 + 材质质感 + 场景环境 + 光影 + 镜头语言 + 风格 + 约束
```

## 镜头过载修复优先级

当镜头信息过载时，必须按以下顺序减负：
1. 保主体与核心动作
2. 保核心场景与主镜头运动
3. 保关键对白与一致性约束
4. 删次级道具
5. 删重复风格词和空洞形容词
6. 删对视频模型无帮助的说明块

## segment 级最终视频提示词排版

最终交付给 `Seedance 2.0` 的版本，必须是**单段连贯总提示词**。

允许先写结构化草稿，用于内部整理：
```text
7秒视频段（0-7秒），@角色 @场景 @道具。
风格：...
0-2秒：...
2-5秒：...
统一要求：...
限制：...
```

但最终交付时，必须把这些信息压缩成一段导演化、连贯、可直接投喂的视频总提示词，避免拆块重复、避免说明书感。

推荐最终形态：
```text
7秒视频段，@角色 @场景 @道具，整体风格……，开场先……，随后……，接着……，镜头保持……，角色与场景前后一致，避免……，画面不要出现字幕，不要出现屏幕文字、字卡、水印。
```

## 最终交付规则

- `分镜表格` 允许逐镜头输出
- `资产生成提示词` 必须与 `最终视频提示词` 放在同一个 `prompt-package.md`
- `最终视频提示词` 必须默认输出成 `segment_001 / segment_002 / segment_003`
- 每个 segment 默认按 `5-15s` 规划
- 段内时间拆解默认用整数秒
- 分段数在满足时长约束的前提下尽量少
- 结构化 segment 只作为内部整理态，不是最终交付态
- 最终交付给视频模型的 segment 必须压成单段连贯总提示词
- 不把角色生图提示词、资产设计过程、三视图说明混进最终视频 Prompt
- 最终视频 Prompt 强制加入字幕/字卡/水印限制

## 引用过满裁剪优先级

当素材、资产或限制项过多时，必须按以下顺序裁剪：
1. 保核心角色
2. 保核心场景
3. 保核心主道具
4. 删次级道具
5. 删重复风格词
6. 删对视频模型无帮助的说明块

## 安全替换与版权风险表达替换

以下规则属于**必须执行**，不是建议：

### 敏感词替换
- 血腥暴力 -> 激烈冲突 / 危险瞬间
- 政治人物真人肖像 -> 中年权威男性 / 年轻女性发言人 / 虚构领导者

### 版权安全替换
- 直接写知名角色名 -> 必须改写成“相似气质的原创角色”
- 直接写知名电影镜头 -> 必须改写成“史诗战争感 / 复古黑帮感 / 赛博都市感”
- 若存在可识别 IP、角色、镜头或品牌风格直接复刻风险，必须改写成原创风格表达后才能交付

## 质量检查（必须执行）

### A. 结构一致性检查
- `storyboard.csv`、`characters.csv`、`scenes.csv`、`props.csv`、`prompt-package.md` 是否彼此一致
- 角色、场景、道具命名是否前后一致
- `segment` 时长是否落在 `5-15s`
- 是否强制加入字幕 / 字卡 / 水印限制
- 是否区分镜头级、中间草稿态和最终交付态

### B. 生成稳定性检查
- 角色是否容易漂移
- 资产引用是否过满
- 镜头是否信息过载
- Prompt 是否过长、过散、过空
- 图生视频引用是否清晰（如 `@Image1`）

### C. 审美与开场检查
- 开场是否有吸引力或建立是否有效
- 如果是短视频平台内容，优先检查钩子强度
- 如果是剧情 / 广告 / 品牌 / 叙事内容，优先检查开场建立、情绪导入或信息建立是否成立
- 镜头是否好看、构图是否有吸引力
- 画面是否有高级感或明确风格价值
- 反转、笑点、记忆点是否成立

### D. 脚本改编质量检查
- 对白是否自然
- 镜头承载的信息是否过多
- 改编后节奏是否顺
- 从文本到视频语言的转换是否成立

### E. 安全与版权检查
- 是否存在明显违规元素
- 是否存在版权风险表达
- 是否已完成安全替换与原创化改写

## 自查清单

每次输出前至少检查：
- 是否符合 `主体 + 动作 + 场景 + 镜头 + 风格 + 音频` 骨架
- 是否写清时间段
- 是否有对白镜头却漏写台词
- 是否存在空洞填充词
- 是否缺少风格或音频信息
- 是否存在明显违规元素
- 是否存在版权风险表达
- 是否能被直接复制到 Seedance 2.0 中测试
- 开场是否有吸引力或建立是否有效
- 镜头是否好看且有吸引力
- 节奏是否顺而不拖
- 脚本改编是否成立
- 整体成片质感是否在线
