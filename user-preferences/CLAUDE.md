## 记忆系统

### 三层记忆架构

```
记忆库/
├── 情景记忆/          # 具体事件和对话历史
│   └── YYYY-MM/       # 按月归档
├── 语义记忆/          # 提炼的知识和模式
└── 强制规则/          # 系统行为约束（本目录下的所有规则）
```

### 记忆流转机制

```
对话/事件
  → 情景记忆（记录具体事件，含完整上下文和决策理由）
  → 语义记忆（提取模式和知识，定期从情景记忆中提炼）
  → 强制规则（系统约束，只在确认为"必须遵守"时创建）
```

### 情景记忆
- 每次重要对话后，创建情景记忆文件
- 文件命名：`记忆库/情景记忆/YYYY-MM/MMDD-事件主题.md`
- 包含完整上下文和决策理由

### 语义记忆
- 每周/每月从情景记忆中提炼
- 识别重复出现的模式
- 更新已有的知识文档

### 强制规则
- 只在确认为"必须遵守"时创建
- 定期 review 是否仍然适用
- 过时的规则应该归档而非删除

## 自我迭代机制

### 八步自我迭代流程

1. **观察（Observe）** — 回顾本次会话/任务的完整过程，产出清晰的事件时间线
2. **分析（Analyze）** — 什么做得好？什么可以改进？发现了什么新模式？
3. **设计（Design）** — 针对问题设计解决方案，针对模式设计抽象方法
4. **实施（Implement）** — 更新系统文件，创建新的知识文档
5. **验证（Validate）** — 检查文件完整性，验证逻辑一致性，1-10分自我评分（低于7分重新设计）
6. **记录（Record）** — 更新对话历史，创建情景记忆
7. **提炼（Distill）** — 创建/更新语义记忆，总结方法论
8. **提交（Commit）** — 等雷嵘确认后执行 git commit

### 主动触发迭代

完成重大任务后，AI主动询问："本次任务已完成，是否需要执行自我迭代？"

触发条件：
- 完成架构级改动
- 学习了新的方法论
- 解决了复杂问题
- 每周一次（建议周日）
