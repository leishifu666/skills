# HTML 预览规则迁移归档

归档时间：2026-06-26

归档原因：雷嵘准备测试 `leishifu-vibe-ui-selector` skill。为避免用户偏好中的 HTML 选择页规则与该 skill 的触发和执行规则重合，已从 `preferences.md` 的活跃偏好中移除以下内容。

## 原关键选择 HTML 预览规则

- 当澄清后仍需要雷嵘做关键选择时，按本规则生成 HTML 选择页。
- 如果选择会影响视觉呈现、布局位置、交互体验、用户感受或最终结果走向，必须生成临时 HTML 选择页，而不是只在聊天里列选项。
- 临时 HTML 文件命名为 `choice-preview-YYYY-MM-DD-HHMM.html`，放在当前项目中。
- HTML 内至少提供 6 个方案，且每个方案必须有真实差异，不能只换文案凑数。
- 页面需要支持点击选择方案，并提供“一键复制选择结果”按钮，复制文本类似：`我选择方案 C：xxx`。
- 生成 HTML 时应调用合适的设计类 skills，例如 `frontend-design`、`ui-ux-pro-max`、`theme-factory`，保证页面有真实设计感，避免模板化、空洞、AI 味太重。
- 雷嵘回复选择后，再按选中方案执行；执行并验证无误后，删除该临时 HTML 文件。

触发 HTML 选择页的典型场景：

- 设计方向、页面风格、视觉调性。
- 按钮样式，如颜色、大小、圆角、图标、hover/active 状态。
- 按钮位置，如左/右、顶部/底部、固定/跟随内容、工具栏内/页面角落。
- 布局位置，如模块顺序、卡片排列、侧边栏位置、弹窗位置。
- 交互动画，如 hover 动效、切换动效、滚动动效、进入/退出动画。
- 组件形态，如卡片、列表、标签页、抽屉、弹窗、分栏。
- 视觉密度，如紧凑、标准、宽松。
- 架构路线、内容选题、多方案执行策略等关键选择。

普通技术确认不触发 HTML 选择页，例如是否继续、是否运行测试、是否读取文件、是否允许安装依赖、是否删除已经确认过的临时文件。
