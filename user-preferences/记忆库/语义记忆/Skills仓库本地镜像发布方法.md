# Skills 仓库本地镜像发布方法

## 适用场景

当雷师傅要求检查、整理并发布本机全部 Skills，且明确“一切以本地为准”时，使用本方法。

## 核心原则

1. 本机当前可被 Codex 识别的 Skill 根目录是唯一内容准本。
2. 上游仓库只用于状态检查，未经明确要求不合并更新。
3. 远端旧内容删除前必须明确：是清空旧 Skill 后重建镜像，还是删除整个仓库。
4. 删除通过普通 Git 提交完成，不使用强推，保留恢复能力。
5. 发布完成以远端提交树和引用为准，不以本地复制成功或推送命令输出为准。

## 标准流程

### 1. 扫描

- 统计含根级 `SKILL.md` 的有效 Skill。
- 运行标准更新扫描器，并补充检查没有元数据的嵌套 Git 仓库。
- 定位专用发布仓库、默认分支、同步分支与远端地址。
- 检查工作区是否干净，避免在实际使用目录直接全量暂存。

### 2. 计划与确认

- 明确本地优先还是上游优先。
- 明确远端旧 Skill 的保留、归档或删除策略。
- 影响多个文件时先给计划，获得确认后再执行。

### 3. 安全镜像

- 使用干净发布工作区。
- 镜像每个有效 Skill，并排除平台管理目录、嵌套 `.git`、密钥、真实 `.env`、缓存、日志、依赖目录、本机构建程序和超大文件。
- 使用明确路径暂存，禁止 `git add -A`。
- Windows 递归操作前解析目标绝对路径并验证其位于发布仓库内。

### 4. Git 边界检查

- 检查是否存在 mode `160000` 的 gitlink；完整镜像必须转换为普通文件目录。
- 检查默认 `main` 是否包含远端新历史。需要本地树获胜时，保留远端父提交并使用普通合并，随后快进推送。
- 提交前检查敏感路径、疑似密钥、大文件、删除数量和作者信息。

### 5. 验证

- 比较本机有效 Skill 根目录与最终提交树：`missing=0`、`extra=0`。
- 查询远端引用，确认默认分支和同步分支均指向预期提交。
- 推送超时先查远端，确认失败后才重试。
- 确认发布仓库与规则仓库工作区干净。

## Windows 特别注意

- Python 读取 UTF-8 Skill 文件时显式启用 UTF-8 模式，避免 GBK 误报。
- 递归删除或镜像前验证解析后的绝对路径。
- 排除 `.exe` 和本机构建二进制，避免 GitHub 大文件限制与机器绑定产物。
- Skill 演进缝合后连续执行两次并比较哈希，确认自动生成章节幂等且只出现一次。

## 验收标准

- 本地与远端 Skill 数量和名称完全一致。
- 没有真实凭据、缓存、日志或机器专属文件。
- 无强推、无未确认删除、无未追踪工作区残留。
- Codex 规则在独立仓库完成单独提交和远端核对。
