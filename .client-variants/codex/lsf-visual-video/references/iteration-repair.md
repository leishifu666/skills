# 失败视频、素材歧义与局部修正

用于用户附生成结果，要求修复结尾、台词、音色、嘴型或动作，或要求提示词更短。以本轮问题为范围，不重做未被否定的设定。

## 1. 先建立观察依据

- 读取媒体实际时长；查看全片概要及问题区间，结尾问题至少检查末尾数秒。
- 分开记录：可见动作、屏幕字幕、音频实听、自动转写及推断。自动转写时间不是音素级对齐；金额、同音字、说话人和笑声尤其要核对。未听到原音时不描述为已确认的声线/语气。
- “结尾不对”至少区分：台词被截断、话已说完但无余韵、动作顺序错、音画不同步、物件穿帮。不得把这些一律诊断为时长不够。
- 不在交付提示词中引用用户不会上传的素材；本地分析视频不自动成为生成器参考。

## 2. 素材职责与脸部结构

给每份实际上传素材一个明确职责：角色身份/脸部结构、场景服装/构图、音色/整轨。发生冲突时按属性选优先级，不笼统说“全部完全保持”。

- 音色参考 ≠ 台词参考 ≠ 音频驱动。只借音色时，唯一正文脚本另列，不继承音频里的自我介绍、笑声或时序。多人分别绑定声线与台词，听者不跟着张嘴。
- 音频入口若仅支持整轨驱动，提示词不能保证提取音色并忽略内容；指出该限制。需要独立配音或口型工作流时，先说明额外步骤，不冒称一句负面提示就能解决。
- 简化角色先确定“哪里是嘴、是否有鼻子、嘴的数量”。让原有嘴部轮廓开合；不生成第二张嘴、人类鼻唇或牙齿。若需要改角色图，给正面单角色嘴型清晰的图像提示词；不擅自生成图片。
- 缺牙等特征在首次张嘴就成立并保持，不先出现完整牙齿再变形。开始闭嘴也要说明内部结构保持一致。

## 3. 对白与动作顺序

每句台词只出现一次，绑定说话人。模型专属标签按对应参考，不把表演说明写进对白。用户已确定的文字不擅自缩写或润色，尤其是金额、买/卖、否定词和梗的转折。

用“前置条件 → 动作 → 可见结果”检查关键交互：例如说完购买意图 → 付款 → 商品交付 → 双手回到车把 → 离开。对话期间可准备动作，但不能提前完成会泄露或破坏笑点的结果。

手中物件要有去处。不要为了完成一串动作增加笔、本子、牌子、额外硬币或临时第三只手。结束优先保住交易结果与人物反应；完整骑出画面未必必要。

## 4. 时长预算与动作强度

- 区分目标总时长与用户界面实际可选值；提示词不能解锁超限时长。不用“如果支持就行”的附注包装一份已知超限的可直接执行成品。
- 以实际对白占用估计剩余时间；对串行复杂动作不要随意各塞一秒。必要时提出简化动作；删台词、拆段或换平台不能作为默认替代。
- 用户说“只加两三秒”时，新增预算优先给未完成动作和短暂收尾，不增加剧情。留多久取决于镜头，不把固定一两秒当成所有场景的硬规则。
- “抖动太大”同时降低幅度与频率，并限定部位：可写“肩部仅偶尔轻动，头和躯干基本稳定”，不必把活人做成静帧。不伪装成精确可控的厘米或频率参数。
- 写清结束状态，避免在半句、半个交接动作中截断。时间码只是目标，不能保证模型逐帧遵从。

## 5. 压缩与交付

短版保留：素材职责与冲突优先级 → 关键动作链 → 唯一台词及语气 → 本次必要限制与最终画面。删掉重复禁令、与参考重复的服饰清单、冗余风格词和无关剧情。

用户要“完整提示词”时返回一个自洽可复制版本，不只追加可能与旧文冲突的补丁。只改局部时不重写全部台词或擅自添加戏份。用户要求中文就用中文；格式与长度指南服从明确交付要求。

发送前检查：实际可用时长、素材编号、单/多段选择、台词不变、音色不带词、嘴部唯一、物件状态、动作先后、结尾停顿、无互斥旧指令。
