# LSF｜产品宣传视频

交付可播放、有音效的成片和可重渲染源码。只有分镜、静态网页或音频计划时，不能称为视频制作完成。

## 已有项目模式

用户提供项目代码、要求用现有产品拍片，或表示原界面不好看时，读取 [已有项目与 UI 呈现选择](references/existing-project-mode.md)。先核对真实能力，再按镜头选择 **原生复用、呈现优化、宣传重绘**；同一片可混用，无须先让用户选择全片模式。原生复用保留当前组件与交互；呈现优化调整取景和画面包装；宣传重绘可换用视频专用组件、排版和视觉风格，不要求先证明原组件无法复用。

用户要求原样展示时遵循原界面；已允许美化时，依据目标画幅的可读性、视觉层级、品牌识别与叙事需要选择，不强制继承不适合出片的 UI。重绘保持真实功能、必要操作和输入输出关系，记录与当前产品的差异，不把宣传界面或演示结果称为原生实录。此选择只作用于视频工程，不构成修改产品 UI 的授权。

需要现成动画或视频专用 UI 时，按需调用 `lsf-remocn`：可用于字卡、背景、转场，也可用于宣传重绘镜头。原生镜头仍使用项目组件；Remocn 的模拟界面、默认主题、画幅和时长不覆盖本片的选择。其组件选型、时钟与 GSAP 分工见上述参考，不默认加载全部配方。

## 输入与事实

- 读取产品代码/页面/用户材料，确定观众、一条叙事主线、行动指引、目标平台、时长和画幅。缺少平台时先做 16:9、约 15–30 秒初稿，说明假设；用户指定优先。整体介绍围绕一个完整用户任务选能力，不按功能数量凑镜头，也不能漏掉用户指定的核心能力或擅自缩成单功能演示。
- 建立 `claims`：每项宣传说法对应代码入口、页面证据或用户提供的事实。识别原型、演示数据、已实现功能；不编造生成速度、业务结果或未实现交互。
- 有粗分镜则保留其叙事意图。有参考视频则实际查看关键帧与转场，并区分观察和推断。分析快转场至少每秒 8–12 帧，边界不清再看原生帧；记录采样精度，不用一秒一帧推测转场过程。
- 按镜头的呈现选择复用组件或重绘。原生复用镜头直接导入真实组件、主题和图标；宣传重绘镜头可重新设计，保留已指定的品牌要素并记录差异。视频场景可独立编排，但不能把新的场景外壳称为应用真实页面。
- 模型/厂商 Logo 优先使用当前界面实际素材；需要补充时查找官方品牌资源，记录来源和使用要求。区分厂商标识、产品标识与模型图标，按实际模型选择流程出镜；图标映射本身不证明模型可调用，不用无关 Logo 暗示接入或合作。
- 原生复用之前必须从当前页面入口追到实际调用点、props 分支和生效样式，并在运行界面核对。文件存在、组件默认样式或旧规范不能证明当前 UI 正在使用它；未使用变量不得作为设计依据。尚未独立抽取的节点或交互 JSX 可在视频样本中展示，不因“没有共享组件”就放弃原生展示，也不为拍片擅自重构业务代码。宣传重绘无需导入原组件，但仍须核对对应的功能和状态依据。

## 操作流程

制作整体产品介绍前，先完成 [产品理解与导演脚本](references/product-discovery-and-direction.md)：理解真实用户目标、页面间关系、输入到输出的数据流与操作方式，再确定成片叙事。不能把组件清单当产品理解，也不能先做动画再拼卖点。需要展示 Agent 时，必须把「用户提供目标和上下文 → Agent 的可见协助 → 用户得到可继续编辑的结果」拍成完整因果链。

0. **先交设计文档与规范可视化 HTML。** 默认同时提供视频作用域的 `DESIGN.md` 和可打开的规范核对 HTML，再进入视频制作。使用适用的设计规范提取与 HTML 技能，先核对相关项目规范、真实 UI、图片资产和已有动效。区分“当前产品依据”和“本片设计”：原生镜头展示实际样式；优化或重绘镜头展示选定的宣传样式与差异。HTML 逐项对应本片涉及的色板、文字层级、尺寸与间距、圆角、材质、组件状态、视觉居中和动效规则。原生样本导入项目原组件；重绘样本可用新组件，自定值标为本片设计，不归为产品原有规范，也不要求复刻无关页面。分镜和素材选择另作制片方案，不能用分镜审阅页或宣传落地页替代规范可视化。不覆盖项目已有设计文档；外部参考注明来源，自定剪辑参数不能归为来源原文。用户要求先确认时，交付这两份后等待确认，不提前生成下一版视频。
   具体取证与展示方法见 [真实 UI 与规范核对](references/design-review.md)。用户确认后记录已认可的版本并继续后续授权工作；不要每次规划或剪辑都重开设计确认。新增未核对的 UI 或设计方向变化时，只补充受影响部分。
1. **确定一句话承诺。** 写出“谁遇到什么问题 → 产品中的哪些动作 → 看得见的结果”。整体介绍用一个作品串联模板、生成、编排、检查、整理等真实能力；功能特写才只聚焦一个操作。宣传标题、功能短句、结束口号默认不加句末句号，标点只在有语义作用时使用。
2. **拆片段并逐段选参考。** 先写每镜让观众带走什么，再选真实 UI、作品、字卡或概念画面。镜头可承担注意、主张、证据、成果、使用情境或品牌任务，不强制集齐或固定比例。每段参考写来源、时间码、实际观看范围、学什么与不照搬什么；不能拿一支整片指导所有镜头。镜头卡记录前后状态、素材身份、可读区间与声音同步目标，每对相邻镜头另写交接卡。用 [导演计划与审看](references/director-plan-and-review.md) 和 [完整故事计划模板](assets/director-plan.example.json) 落地；输入与跨镜细节见 [分段参考、剪辑与输入音效](references/segment-editing-and-typing.md)，分镜依据见 [阅读依据](references/book-method.md)。
3. **先排有声音的动态分镜。** 用静态镜头卡和暂定声音生成低成本 MP4。检查文案阅读时间、动作因果、镜头方向及全片长度；删掉无信息的镜头。无须为常规可逆修改反复索取确认。
4. **把动作绑定到帧。** 根据 [动画与声音规范](references/motion-sound.md) 设镜头、组件运动、文字揭示和转场。使用共享帧事件驱动画面与声音；避免计时器、CSS 无限动画、未固定随机数影响输出。本用户要求宣传片新增的镜头推拉、输入聚焦、图形交接使用 GSAP timeline，按 [GSAP 按帧编排](references/gsap-frame-render.md) 实现。输入镜头建立页面方位、推进到输入区域、稳定打字，再按信息需要拉回发送或结果范围；不每个字都推拉。转场先写两镜的语义、构图、动作或对象关系，再决定硬切、匹配或连续运动；不强迫每镜都有承接物和转场特效。连续旅行检查接点速度，落稳读屏允许归零；原生镜头保留产品动效，重绘与 Remocn 组件可使用各自的帧驱动实现，外层 GSAP 不重复控制同一属性。
5. **制作音效。** 先说明每个声音服务的事件，再试听并选择授权采样，记录来源、许可、剪辑位置与增益。本用户的输入演示要有匹配实际输入节奏的键盘音效，和聚焦、提交、转场声分开；规则见 [输入音效与声音跨镜](references/segment-editing-and-typing.md#输入框与打字声音)。本用户已否定程序合成音轨，精修版不得继续用合成脚本替代素材选音。`scripts/score_audio.py` 和 `scripts/design_audio.py` 只保留为明确需要的早期占位/工程试验，不作为精修默认；两者都是原创工程实现，不是书中附赠工具。下载成功和音量检测都不能替代听审，未听审须说明。
6. **验证并审看后导出。** 执行 `scripts/validate_plan.py plan.json` 检查计划结构与声明；通过不代表成片好看或声音已听审。按 [导演审看](references/director-plan-and-review.md#正常速度审看) 检查信息、快慢对比、原生交互和接缝，分别记录证据与待修问题。再用 ffprobe 验证实际时长、帧率、像素和音轨，检查音量、静音段、完整解码、关键中间帧与首尾。音轨存在不代表已听审。
7. **交付。** MP4、源码、分镜/声音事件 JSON、事实依据与验证记录。说明哪些素材为演示、是否实际听审、未验证的画幅/运行环境；用可点击的绝对路径交付。

新片从 [导演计划模板](assets/director-plan.example.json) 改写故事、事实与素材；它是策划示例，尚未渲染。[三段输入交接示例](assets/segment-plan.example.json) 用于展开交互与采样细节。[旧版时间线](assets/example-plan.json) 仅保留作历史工程样本，不再作为宣传叙事、文案或精修音色的默认模板。示例不能证明当前产品能力。

完整页面、Agent 创作和参考组合的实测范围见 [奶茶海报试跑](references/milk-tea-trial-2026-09-20.md)，包含交互跳位诊断、修正与尚未验证的限制。

## 实现选择

- React 产品优先用 Remotion 按帧渲染；先核对项目已有工具、依赖和当前官方文档。[渲染契约](references/rendering.md) 记录已实测的接入方式。
- 原生组件不能稳定按帧重现时，先录制实际页面再合成；非 React 项目也可走此路径。宣传重绘使用视频专用组件，无须把业务工程迁到 React 或为了复用强改原组件。
- 依赖放视频工程的目录，避免改产品依赖。若项目已有视频工程，复用已有入口。
- 主应用存在副作用时，仅注入视频专用演示数据；不要让渲染触发真实发布、扣费、生成或持久化。
- 真实组件需主题/样式上下文时一并接入。若只补用了哪些 utility 样式，在记录中说明，避免把缺样式的组件误称为“还原”。
- 用户要求与项目交互一致时，优先挂载完整当前页面及其真实控制器，连同全局 hover 初始化、Portal、状态更新和样式一起复用。只换网络/模型/持久化数据边界，记录每个适配点；不得重写一套按钮、连线、聊天面板或用空回调代替正在演示的功能。外部运镜包住整个页面视口，避免 Portal 留在镜头外、缩放后指针与命中坐标不一致。

## 最低验收

- 宣传说法有依据，主卖点能从画面看懂。可以先展示最终成果再回到创作过程；真实操作段内仍保持输入、反馈、结果的因果，不用剪辑暗示零等待或未实现能力。
- 每个 UI 镜头注明原生复用、呈现优化或宣传重绘及其依据。重绘可以更换组件与视觉，但不新增未实现能力；验收其功能映射、画面和编排，不要求与原页面像素一致，也不把它计为原生交互已验证。
- 主焦点在画幅内，文字有稳定阅读段，光标到位后才触发动作。检查整个文字与图形组合的视觉重心，不只检查 CSS 容器中心；对称构图计算可见对象实际尺寸，不能被透明边距或缩略图内部宽度骗过。过渡中可偏移，稳定镜头应有明确平衡。
- 连续动作保持对象身份、左右关系和时间因果；语义跳接、字卡与成果预告允许换对象或时间。每个接缝说清为何这样切、观众视线去哪里，不用统一推拉掩盖关系不清。
- 各段有具体参考及迁移说明，相邻段有独立交接记录；同时检查画面接缝和声音跨镜，不能以单段各自好看替代全片连续性。原生输入特写有真实焦点、实际文字变化、相应键盘声音和读屏停顿；重绘输入核对编排中的焦点、文字与声音，并标明为宣传演示。
- 至少有与真实画面事件对齐的音效，不能仅放一首背景音乐代替音效设计。同类声音须有音色/力度变化，运动声包络跟随速度，有停顿与尾音，避免每一步同样长的 whoosh 和固定循环琶音。
- 成片解码成功，首尾无意外黑帧，音画长度一致，峰值不削波。
- 书中方法、原创工程约定、尚未读到的章节分别披露。试跑只证明所测场景可执行，不证明任何产品都能自动做成佳作。

## MG 编排与真实交互

用户要求 Hypit 拉片或音乐卡点分析时，先调用 `lsf-hypit` 并按其参考视频流程执行实际媒体工具；读 [Hypit 拉片与音乐落点](references/hypit-edit-beat-study-2026-09-20.md)。逐帧确认视觉切点，把混音瞬态、节拍算法候选与实际听审分级记录；同步目标明确是切镜、到位、显现、接触还是停稳。无法听审时保留未知，不把自动 BPM、最近峰值或工具调用当作音乐卡点已经验证。

被反馈“像演示视频、一直在操作、缺少穿插”时，先读取 [宣传片镜头编排](references/promo-shot-mix-2026-09-20.md)。为镜头分配注意、主张、证据、成果、使用情境和品牌任务，再把真实 UI、独立文字、作品与概念镜头围绕同一主线交叉；不能只增加推拉、whoosh 或统一提速。参考包含 Pen、Arrow 2、Linear 三种有抽帧证据的候选编排卡，精确曲线与声音未恢复。

用户上传/指定参考片、要求提取运镜/特效/速度/剪辑，或希望以后自由组合时，按 [参考片入库与重新导演](references/reference-ingestion-and-remix.md) 建立带证据、输入输出契约及参数的技法卡。可检索 [动作配方目录](assets/motion-library/index.json)，并调用配套原创 GSAP 配方。先确定自己产品的故事，再选择/改写参考；原片用于分析，不直接当成我方可发布素材。无法得知原始曲线时明确标注近似，不能伪称精确反演。

原生镜头被反馈“假操作、不丝滑、鼠标僵硬”时，先用 [交互连续性与单镜头试跑](references/interaction-continuity.md) 定位，不立即重做整片。先导出一个 8–12 秒原生交互样本，检查指针轨迹、接触时序、拖拽误差和镜头坐标，再扩展场景。重绘镜头同样检查轨迹、状态、声音与镜头，但不强制接入原生事件或使用原生拖拽审计脚本。浏览器事件成功、组件已导入、60 fps 或 GSAP 已使用，都不能单独证明观感自然。

书籍工作流补充和这次实际读完的章节见 [阅读依据](references/book-method.md)；逐段拉片、官网资料、观看边界见 [2026-09-20 参考拆解](references/motion-study-2026-09-20.md)。复用的是动作关系，不是参考片的配色、素材或完整镜头。

涉及快剪、图片编排、原生动效融入或被反馈“死板”时，按 [MG 编排研究与纠错](references/mg-choreography.md) 检查。原生复用镜头带入相关状态和反馈；保留已选定的本片设计基准。宣传重绘属于视频呈现，不把它误记为产品 UI 已修改。

被反馈节奏平均或声音平淡时，继续读取 [速度反差、纵深与声音](references/rhythm-camera-sound.md)，先区分读屏、镜头旅行与接触落点，再重排时间线；不能只统一加速或调大音量。新增参考包含两支完整视频、四段官网节选及 CC0 音乐 / 空气采样，按实际观看与听审范围使用。

视觉方向已认可、仍需改善配乐和接缝时，使用 [声音选材与连续性精修](references/audio-continuity-refinement.md)：相同画面做响度匹配试听，原帧率检查图片裁切、速度归零和遮罩交接。保留素材许可边界，候选与已听审定稿分开。
