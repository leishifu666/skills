# 从产品理解到导演脚本

此方法是本技能的制作契约与案例经验，不伪称书籍原文。分镜依据仍见 book-method.md，剪辑依据见 segment-editing-and-typing.md。

## 先理解用户怎样完成任务

1. 找到当前页面入口、路由、实际组件分支、主题及全局动效初始化。核对本地技能/旧设计稿是否过期，以当前源码和实际页面为准。
2. 走通一个「输入 → 操作 → 状态反馈 → 输出 → 再使用」的任务。记录真实按钮名称、鼠标/键盘用法、参考素材如何传入、执行在哪里发生、结果保存在哪里。不能用文件名推断可用功能。
3. 写 product-brief.md：目标用户、具体任务、3–5 项可串联能力、页面关系、输入输出、能力限制和证据。每项区分代码支持、运行界面已观察、端到端已执行、演示数据；未接通服务不能标成端到端实测。
4. 按因果选页面，不追求所有菜单露一遍。构建一个连贯案例：同一品牌、同一主体、同一批素材，从需求到成品再到复用。涉及多个工作区时，说明切换原因，禁止借用另一个工作区的控制栏冒充当前页面。

## Agent 的导演方式

如果 Agent 是产品核心能力，不可只拍一个空聊天框或罗列「有 Agent」。至少展示：

- 用户的任务，以及引用的图片/节点/文档；实际使用 @、上传或项目支持的选中引用交互
- Agent 当前可观察的工作：读取上下文、调用技能、创建/连接节点、生成/编辑等，只选已实现能力
- 产出落在哪里，用户能怎样检查、修改、继续创作或保存

明确 Ask/Auto、确认步骤与模型配置要求。若用演示回放，替换模型返回和存储边界，仍让原生输入序列化、引用 chip、发送回调、事件流、画布补丁应用器和交互控制器执行。记录引用 ID 与实际连线证据，不能仅在回复里写「已参考图片」。不凭空承诺任意任务都能成功，也不把剪辑压缩的等待当真实生成速度。

## 开拍前写 director.md

必须能回答「成片长什么样」：

- 一句话承诺、观看对象、片长、画幅、无旁白/旁白、开场怎样抓住注意、结尾留下什么
- 每段：信息任务、观众此刻要看懂的变化、真实操作步骤、起止状态、页面/组件、素材 ID、文案、景别、声音与自己的参考时间码
- 每个接缝：承接对象、视线落点、运动方向、出入速度、遮罩/剪辑方式、声音跨镜
- 节奏图：交代、操作、结果、旅行。阅读/接触时稳住；镜头旅行可快，不能全片同速
- 资产清单：现有资产或待生成资产、用途、主体一致性、画幅和来源。缺图可用可用的生图或 PPT 工作流补充，工具由素材需要决定，不为用工具而制造无关内容

默认同时给可视化导演 HTML，展示分段、实际素材和引用关系；它与 DESIGN.md 的组件规范 HTML 是不同交付物。已获制作授权与设计确认时继续制作，不重复设置确认门槛。

## 保持产品原有交互

优先直接挂载完整页面，复用其当前 CSS、GSAP/原生动画、全局 hover 控制器、Portal、节点控制器和事件处理。检查全局入口初始化，导入 JSX 不代表 hover 系统已启动。

模型/网络/存储可注入演示边界，但展示的按钮回调不得为 no-op。若确需重建部分交互，先记录偏离并修正，不能仍声称与原产品一致。

宣传新增 GSAP 只负责页面外的镜头、版式和转场，不重写按钮反馈、不改产品内部缓动。需要在外层缩放含 Portal 的页面时，使用完整视口容器（例如同源 iframe）让内部坐标和浮层保持一致。指针、真实输入与镜头使用同一时间轴，点击不瞬移，按下与抬起至少能被渲染采样。

## 验收与边界

- 逐项对应 product-brief 的能力证据，逐段对应导演脚本
- 检查当前原生 hover/active、引用 chip、文字变化、发送、节点/连接结果、保存反馈，不仅看最终截图
- 检查完整开场、关键转场中间帧、鼠标运动速度和点击命中
- 交付播放成片、可重渲染源码、脚本、素材/声音来源及验证记录
- 演示服务输出与真实在线执行分开；没有听审就不写音质已确认
