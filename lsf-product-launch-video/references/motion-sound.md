# 动画与声音的执行规则

以下是原创工程约定，作为起点按作品调整；不是书中的固定数值。

## 一份时间线驱动所有输出

`plan.json` 包含 `fps`、`durationFrames`、`width`、`height`、`scenes`、`events`。镜头采用左闭右开帧区间。每个 scene 至少有 id、startFrame、endFrame、message、focus、action、evidence；每个 event 至少有 id、frame、durationFrames、kind、gain、pan、visual。

- `frame` 指声音开始时间；如果落点应与视觉峰值一致，让声音包络的峰值对应该帧，并在记录中写偏移。
- `visual` 记录事件所对应的可见动作；不靠“差不多在这时候”排音效。
- 把 `events` 同时导入画面代码和音效脚本。修改动作时间时，改同一处数据。
- `music` 可设 enabled、bpm、gain。没有音乐需求时关闭，但保留必要交互声音。

## 选择动画

| 目的 | 起始建议（30 fps） | 验证方式 |
|---|---|---|
| 控件被操作 | 按位移距离、目标尺寸安排接近时间；到位、hover、按下、松开分别记录 | 查命中与接触前后帧；长距离不能机械套 8–16 帧，异步结果保留真实阶段 |
| 元素进入 | 12–20 帧淡入/位移，轻微弹簧可选 | 清晰度恢复后再读文字，避免全场一起弹 |
| 镜头推进 | 18–30 帧；围绕要看的内容缩放 | 检查最大缩放帧的焦点和裁切，不放大无信息角落 |
| 揭示差异 | 掩模/滑块跟随连续位置，保留同一主体对齐 | 原图与结果身份、基准位置不跳变 |
| 转场 | 6–12 帧遮挡/匹配切换；读完后再走 | 写明继承对象/颜色/方向，无理由则直接切 |
| 文字 | 标题稳定显示至少约 1 秒；长句实际计时 | 静音播放还能理解，不把文字大半寿命耗在动画上 |

产品原有按钮的 hover/active 按产品规范保持；镜头运动不应被误写进业务组件样式。动画类型的数量不作为质量目标。

## 声音分工

- `click` / `tap`：按钮接触、选中，短、干净；与键盘声音分工。
- `type`：可见输入过程的键盘声音；按实际输入短组和停顿安排同音色变体，不能漏掉整段，也不能每个汉字等间隔重复一个点击。见 [输入音效](segment-editing-and-typing.md#输入框与打字声音)。
- `swish`：镜头或拖动；匹配运动时段，收尾自然衰减。
- `thump`：大块画面落位或强调信息；不用于每次点击。
- `chime`：操作完成或品牌收尾，使用克制的短音型。
- 音乐底承接整体节奏，不能盖过事件；有旁白时给旁白优先权，必要时降低底乐。
- 使用授权采样，记录来源。本用户已拒绝程序合成音轨，除明确要求工程占位外，不以合成音效代替选音；保留原录音质感。

## 音频与画面检查

1. FFprobe 确認音视频轨和长度；AAC 封装可能带微小 padding，按帧容差判断。
2. 先输出有声 animatic，检查主要事件时间，再细化动画。
3. 使用 FFmpeg `ebur128=peak=true` 测响度/真峰值。-1 dBTP 是本技能的输出上限约定；需要平台规范时另查。
4. 不为达到某个响度数字抬高空白段和底噪；调整素材增益，再复测。
5. 静帧能检查构图，不能证明节奏；时间线、转场帧和播放检查各自记录。
6. 若环境不支持听审，明确只完成音频信号和事件同步验证，把试听列为剩余项。

`score_audio.py` 是标准库占位音工具，保留用于早期分镜，不作为精修默认。它使用固定种子、立体声等功率声像与边缘包络；峰值仅向下缩放至 -3 dBFS。输出报告记录实际采样峰值，不把采样峰值当真峰值。

## 避免机械音效

`python scripts/design_audio.py plan.json mix.wav --motion motion.json` 仅保留为占位和工程试验，需 NumPy；不作为本用户精修音轨。省略 motion 时仍可按事件设计；提供时须与计划帧数一致，每帧含 0–100 的 pos，用其速度调制拖动声音，位置调制声像。该 pos 契约仅对应滑块，其他运动自行提供合适的速度控制，不要把旋转角度直接冒充位置百分比。精修改为授权采样，见 [MG 编排研究](mg-choreography.md) 的素材来源和听审要求。

- `tap`、`connect` 的接触音与连接确认音分开，同类声音改变频率，避免每次都像按同一个电子琴键
- `air`、`sweep`、`rise` 区分空气移动、形状转场和增强预期；包络随运动变强变弱，不用一整段等音量白噪声
- `drag` 跟随速度，在动作两端和停顿处变弱；声像只小幅跟随位置
- `bloom` 与 `resolve` 分别用于结果和收尾，不给每个事件都叠和弦
- `soft` 是柔和低频落点，`type` 是不规则分组短触感，避免每字都使用同一种响亮点击
- 可选 `beds`：数组元素为秒单位 start/end 与 Hz 单位 frequency。仅在指定段落铺低音量持续音色，留出比较/阅读的静音空间；不默认循环旋律
- 需要“更好听”时先检查事件密度、音色对比和停顿，再考虑加大音量。参数验证不能替代实际听审

声音落点要区分“开始帧”和“峰值帧”。气流声可随加速逐渐达到峰值；点击和接触音应贴近触碰动作。发生运动时间调整时，重新从同一事件计划输出音频。

画面剪切与声音剪切不必同帧；按 [分段剪辑与声音跨镜](segment-editing-and-typing.md) 指定 J-cut / L-cut 或连续音乐。跨镜尾音由主时间线保管，不在每个片段尾部自动截断。先读屏再加快旅行，不能让音乐节拍强迫用户看不清操作。

## 视觉居中与交接验收

1. 在稳定镜头截取完整画面，按可见文字、图像、控件的范围看整体，不按透明容器居中
2. 模板卡、画布节点、图库缩略图采用对称布局时，使用实际渲染宽度计算中心，检查内部子组件是否更窄
3. 输入框较矮时标题靠近；容器变高时标题同步上移腾出空间，不让二者一直隔着大块空白
4. 新内容须继承变形容器的当前尺寸，不能在容器展开中途突然以终态尺寸淡入
5. 下一镜标题避开仍未退出的旧主体；检查过渡 25%、50%、75% 时刻，比只检查首尾更容易发现遮挡
6. 强调卡片或圆形遮罩的转场起点必须精确对齐上一镜的可见对象，不能只是“大概从附近展开”
