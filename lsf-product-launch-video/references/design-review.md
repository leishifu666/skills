# 产品依据与本片设计核对

用于有现成产品的宣传片。按 [已有项目与 UI 呈现选择](existing-project-mode.md) 区分原生复用、呈现优化和宣传重绘。目标是核实当前产品依据，并看清本片采用的样式及改动；原界面不好看时，不要求把它完整搬进视频。

## 从当前界面取证

原生复用按「页面入口 → 实际调用 → props 分支 → 生效样式 → 运行画面」核对准备出镜的组件。宣传重绘核对对应功能、输入输出、必要操作和要保留的品牌素材，不要求导入原组件或沿用旧样式。记录与镜头有关的证据即可，不做全仓库审计。

- 旧规范与当前界面不同，明确列出差异；产品依据以用户要求展示的版本为准，新的宣传样式另列，不为拍片修改产品实现
- 同名组件的默认分支不等于页面使用的分支；桌面按钮和节点按钮可能来自不同组件
- 样式函数、变量和组件必须确认被当前链路使用，不能仅凭文件名称选取
- 节点无需事先抽成共享组件；可以复用当前 JSX 和依赖，放入视频专用样本，不改业务结构
- 图片、字体、图标、主题上下文与原有 CSS 一起核对，检查资源成功加载，避免组件导入了但外观不完整

## 两份交付各司其职

视频作用域的 `DESIGN.md` 区分当前产品依据与本片设计，写相关颜色、排版、材质、尺寸、组件与运动规则。原生取值给出来源；重绘可以制定新的规范，但标明为本片设计，不从几个局部值推导不存在的产品全局规范，也不覆盖项目原文档。

配套 HTML 是规范与组件的可视化样本册。让文档规则紧邻对应样本，展示实际值与来源，并提供与拍片有关的交互：

原生样本复用原组件与状态；重绘样本展示新组件、状态编排和与原产品的差异，可按需放相关原页面对照。下列条目只选本片涉及的部分；纯重绘片无需另做一套完整原生组件册。

- 深浅主题、文字在不同背景上的配色、整体视觉重心
- 原生按钮的可用/禁用/运行状态按当前实现展示；重绘状态有功能依据，不将统一的新外观说成原样
- 输入栏收起/展开、节点空态/结果、选中/取消、端口与浮层
- 可重播或可操作的原生或重绘动效，标明来源；静态截图不能替代运动检查
- 真实图片与模板封面标明类别；互不相关的图片不当作前后结果

章节与控件数量取决于本片要展示的内容。样本数据与操作处理器应隔离，防止预览触发真实生成、扣费或写入；原生样本保留外观和交互反馈，重绘样本按所选设计呈现并说明编排方式。示例输入与历史作品不描述为现场生成。

不要用故事板、整页宣传落地页或几张色卡替代上述 HTML。故事板另存制片方案，避免用户分不清是在确认产品规范还是确认广告创意。

## 检查与确认

打开生成的 HTML，实际检查本次涉及的状态切换、素材加载与动效，覆盖目标桌面尺寸及窄窗口。重绘检查本片设计和功能映射，不与旧 UI 做像素一致性验收。只有组件测试通过，不能声称完整产品业务已验证。

用户确认后，在制片方案记录认可的 DESIGN.md 与 HTML。沿用已确认基准；用户要求先规划时只交规划，不将设计认可扩大为成片制作授权。后续改镜头与音效通常不需要重新审整个设计系统。

## 坤坤魔法的已验证例子

2026-09-19 的核对发现：BottomInputBar 实际传入 GenerateButton 的 forceDark 分支，显示玻璃箭头；节点图片面板使用 GlassSendButton。旧的星光图标加「生成」文字不是这两个页面当时的当前按钮。输入栏中存在未用于当前渲染的旧样式定义。

节点样本复用了 NodeShell、TextNode、ImageNode、VideoNode、CompareNode 与原有浮层动效。这个例子说明需要追踪调用链，不意味着以后所有项目都使用这些组件或固定尺寸；再次出片仍检查源代码是否有相关变化。
