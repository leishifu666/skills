# 快剪的速度反差、纵深与声音

适用：用户反馈节奏平均、音效平淡、图片像幻灯片，或要求参考 Bohdan / Flashmotion 一类产品 MG

证据入口：[6 段参考的可视化拆解](../assets/mg-rhythm-research-2026-09-19/research-review.html)；[完整观察记录](../assets/mg-rhythm-research-2026-09-19/研究结论.md)

## 先看什么

- BoltForge：9.8–11.2 s 的推近 → 点击 → 拉远，原生 25 fps 连续帧；28.5–34.5 s 的箭头 → 图片 → 作品群
- Bolt Slides：7.5–10.3 s 的纵深队列 → 编辑器侧栏；12.5–18.5 s 的真实编辑与读屏停顿
- Creative Force：2.4–5.2 s 的斜置 → 卡片落位 → 转正 → 保留同一卡片交接
- Dreem：1.5–3 s 的容器边缘极近景 → 上传框
- Secureframe / Appspace：只看主形状与文字语义分组，不把与产品无关的盾牌、发光色搬进广告

前两支是完整文件，后四支是 4.76–5.68 秒的官网无声节选。作者公开确认 Creative Force 使用 AE 3D 相机、景深和自定义模糊转场；具体 GSAP 参数是我们的实现选择，不能归给原作者。音频只有文件与信号分析，没有实际耳听结论。

## 直接执行

1. 先标语义事件：选中、输入、连接、发送、完成、展开、品牌。事件先于效果
2. 把每段标为「读 / 走 / 击」。读用于信息，走用于相机旅行，击用于接触或硬切。连续三段时长相近时，检查是否又排成均速
3. 可从读 0.75–2 s、走 0.2–0.45 s、击 0.1–0.2 s 起步；这些是自定范围，按实际字数、帧率与故事调整，不是公式
4. GSAP 编排相机：读输入时停住；发送前快速推近；光标到位 → 原生接触反馈 → 回调 → 拉远交给正在运行的目标
5. 按钮保持产品 hover 规则，快慢和冲击主要由镜头承担，不给普通按钮擅自添加缩放弹跳
6. 交接同一对象要匹配位置、尺寸、裁切、旋转。原生 WebGL / Three 场景可读取 shader uniforms 的屏幕几何再映射到下一层，不用两张近似大图叠着淡出。旋转角先归一到 −180°…180°，避免累计多圈角度被直接插值造成无意旋转
7. 作品组保持至少两张同时可见，用近远尺寸、遮挡和位移速度形成空间。移出节点 → 纵深队列 → 群像停留 → 品牌交接，可连成一个段落；不按文件顺序逐图全屏播放
8. 大运动中短暂模糊，稳定时恢复清晰。不要把每个镜头都做成同长度的淡入淡出
9. 先做包含输入、点击、运行、结果、转场的 8–10 秒带声检查段，再扩展全片

## 声音从稀疏变为有结构

V4 只有短 UI 采样，20 ms 分析窗约 81% 低于 −45 dBFS。技术可运行不等于用户认可；该版本被反馈均速、声音平淡，不作为风格合格标杆。

采用三层：

- 音乐：给节奏和段落，读屏时压低，结果前可安排短空隙；不靠提高总音量解决平淡
- 运动声：短扫动对齐快速旅行，长扫动对齐大展开；按速度改变长度和声像，避免一条原样循环
- 接触声：点击、键盘、选中、完成；动作成立才放，键盘按短组而非每字同声

主音乐在重拍处已经足够时减少附加撞击。允许在预期段收掉音乐再重入，不把所有音效堆满。结束保留尾音。

## 验证边界

渲染证据：真实组件回调、状态、匹配矩形、首尾和转场中间帧。视频证据：完整解码、声画时长、帧率、无意外黑帧。声音证据：采样许可、峰值、响度、是否耳听，分开写。

V5 是规则应用试剪，尚未得到用户视觉或听感确认。后续反馈优先于本例参数；不要把任何一个版本自动写为最终审美标准。
