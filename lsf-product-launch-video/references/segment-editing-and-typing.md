# LSF｜分段参考、剪辑衔接与打字音效

2026-09-20 补充。适用：完整产品片、输入演示、多场景衔接；回应用户要求“不同片段有不同参考”。本轮实际阅读文章/文档，复用此前已拆看的视频，不声称新增视频听审或成片验证。

## 先按段组织参考

1. 按**信息任务**拆片段：引出产品、输入意图、操作证明、结果检查、作品组织、品牌结束。一段可含多个镜头；片段数和长度随内容调整，不平均分配时间。
2. 为各段挑一段主参考；有不同问题时补一段交互或声音参考。参考必须落到明确时间码，且注明文件/URL、查看方式与精度。可以复用同一作品的不同区间，但说明各段分别学习什么。文字文章是方法依据，不能冒充已看过的镜头。
3. 每个片段卡写：`id / 目的 / 真实页面及组件 / 前后状态 / 素材ID / 主参考及时间码 / 观察 / 迁移 / 禁止照搬 / 入镜和出镜焦点 / 声音 / 验证状态`。默认不增加固定参考数量；缺某类参考就继续查或标明待研究，不能硬填。
4. 不同参考服从同一片子的颜色、字体、产品 UI、主作品身份、主要运动方向和声音风格。选择的是可迁移的动作关系，不是拼贴不同品牌。
5. 把每段参考、首帧、关键动作帧、末帧放进导演审阅 HTML；点击可打开参考对应区间。旁边写“借鉴之处”与“本项目实现”。规范可视化 HTML 仍负责核对 DESIGN.md，不拿它代替分镜。

## 镜头之间怎么接

先判断两镜关系，再选剪辑方式。术语用于说明选择，不要求每片集齐全部类型。

| 方式 | 什么时候用 | 本技能落地时检查什么 |
|---|---|---|
| 硬切 Hard cut | 明确的新信息、景别切换或节奏强调 | 焦点位置、动作因果和阅读时间；硬切不等于不自然 |
| 动作剪辑 Cut on action | 同一个动作换景别/视角 | 动作相位连续，接触不能被重复或跳过；UI 可从按钮特写切到同一次运行反馈 |
| 匹配剪辑 Match cut | 图形、构图或运动关系连接两镜 | 明确匹配依据。若是同图换容器还需核对图片内部裁切；若是不同对象，不假称同一对象 |
| 连续推拉 Dynamic zoom | 从整体进入有意义的局部，或局部展开上下文 | 有可追踪的焦点/框中框，方向与尺度变化连贯；不随机朝页面中心放大 |
| 遮挡/擦拭 Wipe | 前景对象穿过镜头，顺势换场 | 遮挡确实覆盖切点，方向被下一镜接住；不要半透明叠出两套 UI |
| 形态变化 Morph | 不同对象存在可解释的形状关系 | 中间轮廓、重心与身份线索可读；只换图片再放大不算形变 |
| 叠化 Dissolve | 时间或状态段落需要柔和省略 | 检查重影与文字冲突；不要所有镜头都等长淡入淡出 |

### 每对相邻镜头写一张交接卡

- `from / to / reason / technique / startFrame / cutFrame / endFrame`
- `carryObject`：具体对象或明确的匹配线索；没有则写无，并说明硬切理由
- `exitState / entryState`：同一屏幕坐标系下的位置、尺寸、裁切、旋转、圆角、透明度、焦点
- `motion`：切点前后屏幕运动方向、速度趋势、相机状态；是继续旅行还是有意停稳
- `audioBridge`：声音归属哪一段、开始和结束在哪、主要落点在哪；是否提前进入/延续尾音
- `checks`：原生帧率检查范围、继承对象误差预算、需要稳定阅读的内容

“慢→快→慢，在快运动中交接”可作为候选，不是必须在最大速度帧剪切的公式。有因果的接触、读屏、品牌停留可以停稳。持续旅行时不要把前段 ease-out 到零、后段重新 ease-in；共享一段相机运动，或检查两段接点的速度/切线。位置连上而速度骤变，也会像顿了一下。

## 声音怎样跨镜

- **J-cut**：下一镜所属声音先于其画面开始。产品片可用下一段的氛围/音乐进入引导期待；成功声不能抢在真实成功事件前响。
- **L-cut**：上一镜所属声音延续到下一镜画面。例如结果展开后的余响保留到作品群镜头，不在画面切换时斩断。
- 全片同一首底乐持续播放不自动叫 J/L-cut；一条无所属场景的 whoosh 可只标“转场音”。分别记录画面切点、声音起止、瞬态/峰值，避免术语代替时间设计。
- 配乐段落按乐句、重音和收束位置剪，不只按 BPM 格子硬切。结尾优先选择音乐自身合适的收束或可兼容的落点，保留衰减；必要时微交叉淡化，不能用淡出掩盖听感未完成。
- 改变分段长度后，从主事件表重排跨镜音频。输入区留出听觉空间，结果段可增强；不每次换镜都叠重撞击。

## 输入框与打字声音

本用户要求输入演示有键盘声，保持无旁白。该要求用于当前产品片，不擅自给业务 App 安装声音功能。

1. **先明确输入模式**：物理键入、IME 组词提交、粘贴、自动填充或流式生成。它们的文字变化和声音不同；流式生成不默认伪装成键盘输入。
2. **画面动作链**：指针抵达真实输入框→原生焦点/光标→GSAP 推进到合适景别→输入时稳定→句段后短读屏→拉回模型/发送入口。镜头不跟着每个字抽动。
3. **记录输入事件**：将 `eventId、timeMs、inputType、isComposing、textDelta、selection/caret` 记录到同一事件表；回放通过真实组件输入路径。中文组词多次按键可能一次提交多个字；不能把字符数当敲键次数。若是分组插入的演示，标明“剪辑后的输入演示”，不冒称真实输入法录制。
4. **选择声音**：SND 官方 `type` 设计含五个微差采样，可减轻连续重复；也可选授权真实键盘录音。风格和现有接触声统一。先试听合适音色，不因为文件叫 type 就判定好听。
5. **安排节奏**：有真实按键记录时对应敲击；只有组词提交记录时，使用与组词时段对应的短组拟音并披露，不能声称逐键同步。短组间允许思考停顿。粘贴/自动填充只需相应操作声，不配一长串键盘声。退格、回车只在动作发生时出现。
6. **变化可重现**：在 cue 中记录实际 `sampleId、sourceInMs、durationMs、gain、pan`，从微差采样固定选择，避免连续同音；不要回放一次随机一次。保持音量克制、声像接近输入位置，避免通过夸张变调制造“不同按键”。
7. **区分聚焦、键入、提交**：聚焦是轻接触；输入是一组键声；发送只有对应的接触落点，运行/完成另有事件。别每个字都触发完成音，也别为了避免重复而漏掉整个输入段。
8. **验证**：先静音检查实际文字与光标，再只听键盘与接触轨，最后听完整混音。字不动时仍连续敲、停止输入后出现多余新敲击、输入已结束却突然补一串声都需返工。保留自然尾音不等于允许多余按键。

来源术语与实现分开：MDN 的 composition 事件说明输入语义；SND 的变体说明选音方法。具体 cue 编排、固定随机种子、预算和拟音方式是本技能工程约定，不是官方规定的节奏。

本机已有候选：项目 `outputs/audio-motion-refinement/audio/SND02_piano/type_01.wav` 至 `type_05.wav`，以及 `SND03_industrial` 同名文件。本轮核对文件存在，没有新试听；使用时重新核对许可，不把 WAV 放进 skill 分发包。

## 片段制作与拼接

1. 参考映射和交接卡先进入计划；选最难的**两段加中间接缝**做带声试剪，不能只测单个镜头。
2. 每段可独立制作、缓存和重渲染，但沿用共享字体/色彩/主素材/相机坐标和 master fps。片段主区间左闭右开，按总片时间排列；转场余量可重叠，主区间不重复计时。
3. 按交接的实际需要保留头尾余量 `handleInFrames / handleOutFrames`。示例可先留约 0.5 秒再调整，不把余量当必须在成片多播的时长，也不把真实事件在预滚中重复执行。
4. 主时间线负责继承对象和跨镜声音的唯一实例。音频总线保留尾部，片段不要各自加淡入淡出或重复底乐。
5. 单段检查可读性、原生反馈、输入同步；相邻段检查切点前后原生帧与中间态；全片以正常速度检查节奏弧线，再慢放定位问题。快剪仍应有证明操作的慢段。
6. 交付每段参考卡、clip、交接卡、主时间线与声音事件。确认后的局部修订只重做受影响片段与邻接缝，不无故重置已认可风格。

字段示例见 [三段计划](../assets/segment-plan.example.json)。它通过基础计划校验，但只是一份待制作的策划样例，音色未听审、组件挂载与交接未渲染，不可标记成片已完成。

`validate_plan.py` 只检查已有帧区间与基础声音字段，不会验证参考内容、继承几何或中文输入。`references / transitions / typingGroups / audioAssets` 是本次增加的计划字段；渲染器和采样混音器需要显式读取，旧合成脚本不会自动执行这些字段。不要把此计划直接交给振荡器占位脚本当作授权采样成片。
