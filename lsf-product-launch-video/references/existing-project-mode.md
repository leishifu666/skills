# 已有项目与 UI 呈现选择

用于有项目代码的产品视频，包括“用真实组件拍”“界面不好看，宣传片美化一下”“原界面与概念镜头混合”。这是接入与呈现规则，继续复用主技能的产品理解、导演、声音和成片验收；不单独启动另一套制作流程。

## 按镜头选，允许混用

| 选择 | 适用情况 | 可以改什么 | 验证重点 |
|---|---|---|---|
| 原生复用 | 教学、操作证明、用户要求原样，或当前界面适合出镜 | 摄影机、画外字幕与包装；页面组件和反馈沿用当前实现 | 当前页面、主题、实际组件分支和交互是否一致 |
| 呈现优化 | 产品 UI 可用，但全页过密、主体过小或取景不佳 | 裁切、放大、聚焦、外围背景、容器和画外注释 | 保留的界面与必要上下文、状态、操作是否真实；裁切是否影响理解 |
| 宣传重绘 | 原 UI 不适合目标画幅、需要新视觉方向或用图形表达能力 | 视频专用组件、布局、颜色、字体、间距和动画；可用 Remocn UI | 真实功能映射、品牌要求、输入输出与必要操作是否保留；呈现差异是否说明 |

改变页面内部布局、文字样式或组件外观就按宣传重绘记录，不能用“优化”掩盖重设计。混合指同一片按镜头使用上述选择，不是第四套实现。

用户明确指定的方向优先。未指定时，检查实际页面在目标画幅下的文字可读性、信息层级、留白、品牌识别和动作可理解性，再给出选择与理由；不仅凭代码猜界面好坏，不要求用户先选模式，不规定原生 UI 的最低占比。用户已要求美化时可直接重绘，无须先尝试把每个原组件搬进视频。

## 真实功能与画面设计分别取证

- 从当前入口追到要展示的功能和输入输出，区分代码存在、运行画面已观察、端到端已执行和演示数据。前端按钮或图标存在不证明服务已经接通。
- 每项宣传说法仍有 `claims` 依据。重绘可以改善表达，但不增加不存在的按钮能力、结果类型、自动化程度、集成关系或速度承诺；被剪掉的必要操作和等待不能被描述为产品自动完成。
- 原生样式检查实际调用分支、主题、字体、图标、素材和依赖上下文。重绘无需保留不好看的样式；明确用户指定的 Logo、品牌色等哪些必须保留，其他值作为本片设计。
- 在视频 `DESIGN.md` 和核对 HTML 中区分当前产品依据与本片呈现。只展示相关原生样本和重绘差异，不为拍片复制整个设计系统。
- 来源与差异默认记录在制片方案和交付说明。重绘画面或编排操作足以被误认为当前产品实录时，在画面或随片说明中注明“界面演示”或“概念呈现”；无需给每个镜头叠加技术标签。

## 接入路线由状态与时钟决定

在用户原项目目录内复用已有视频工程，或增加独立的视频子目录；依赖和适配集中在视频目录，不创建 worktree，不为拍片修改产品默认主题或重构业务组件。

### 可直接导入的组件

适合 React 中可受控的界面局部、静态结果或组件特写。一起接入所需主题、样式、字体、资源和 Provider，处理路径别名并确保 React/ReactDOM 使用同一实例。不要把整个生产入口当纯组件无条件执行。

可由 props 展示的状态按帧提供明确的演示数据。此方式能证明原组件在给定状态下的外观，不能冒充真实点击、输入或后台执行的测试。宣传重绘也可使用纯帧状态，此时组件来源可以是视频专用实现或 Remocn。

### 完整页面与复杂交互

需要证明原生操作时，运行当前页面和真实控制器，接入路由、状态、hover 初始化及 Portal；仅在网络、模型、存储等边界注入演示数据，避免拍摄触发真实发布、扣费或写入。回放从干净前态开始，按页面真实输入事件执行，保留需要展示的反馈。

不能统一控制 CSS/WAAPI、RAF、计时器或组件内部动画时，先录制真实运行的页面，再合成运镜和其他素材；非 React 项目同样可走此路。不要假设顺序点击一次便能在 Remotion 任意帧或并行渲染中重建状态。能独立按帧重现才使用离线采样，并核对重复渲染与跳帧结果。具体原生操作见 [交互连续性](interaction-continuity.md)，按帧接入见 [渲染契约](rendering.md)。

### 宣传重绘

根据已核对的任务和结果构建视频场景，无须导入原按钮或控制器。可抽出真实作品、数据、代码或图标，与新界面组合；组件形状、密度与动效由镜头需要决定。画面中的点击与状态变化可以编排，但交付记录必须区分这类演示和原生交互。新外观仅存在视频工程，不回写应用。

## 按需接入 lsf-remocn

1. 先确定镜头的信息任务，再读取已安装的 `lsf-remocn`。从 `https://remocn.dev/llms-components.txt` 找候选，只打开选中组件的文档；不猜组件名称、props、依赖或时长，不把动态目录复制进本技能。
2. 字卡、背景和转场可用于任何模式；视频专用按钮、对话框、聊天框等可用于宣传重绘。原生镜头的 UI 仍来自项目。现成模板里的模拟终端、聊天界面与示例指标不自动成为本产品能力或素材。
3. 在视频工程按文档安装所选组件，先检查既有依赖和样式，避免覆盖项目同名组件、修改业务主题或重复安装不兼容的 React/Remotion。目录或文档不可达时暂停该组件的接入，可继续已有素材与可验证的实现，不猜接口。
4. 区分 Animation tier 与 UI Primitives：按各组件文档使用帧驱动或状态驱动接口，不假设所有组件都有 `speed`。本片画幅、帧率、品牌和叙事优先；检查组件在目标尺寸的布局、自然动作时长和阅读停留，不照搬模板的固定时长。
5. Remotion 负责帧与合成；新增镜头推拉、输入聚焦、图形交接继续由 GSAP timeline 采样驱动；Remocn 内部保留其帧驱动实现。用外层容器分开运镜和内部效果，同一属性只由一套系统控制；统一主时间线与镜头局部帧的换算。
6. 本技能的真实功能依据、声音要求和验收继续适用。Remocn 是可选实现来源，不成为每片的必装依赖；不整体复制它的产品演示配方或替换现有导演流程。

## 镜头来源记录与现有计划兼容

在导演计划中按镜头记录：呈现选择及理由、功能依据、画面来源（组件路径/页面/录制素材/新组件）、演示数据、改动范围、实际验证与未验证项。可放在导演文档的表格以及现有 `scene.evidence` 文本中，无需新增计划版本。

现有 v2 `presentation` 继续表示画面类型：

- 原生复用，以及只改变外部取景包装的优化镜头，使用 `native-ui`，在 `evidence` 写明裁切或适配。
- 重绘的宣传界面使用 `concept`，在 `evidence` 写明真实功能依据、重绘范围和编排操作。
- 作品与独立字卡继续使用 `artwork`、`typography`。同镜含多种元素时记录主要呈现及各层来源；出现重绘交互界面时不将整镜标成原生实录。

`validate_plan.py` 检查既有结构，不能验证 `evidence` 的事实、界面是否真实或选型是否好看；来源核对仍由制片与审看完成。不要增加它不支持的 `presentation` 值。原生 `reviews.nativeInteraction` 只覆盖实际原生镜头；全片没有原生交互时可填 `not-applicable` 并说明理由，混合片不能把重绘通过当作原生通过。

示例：一支协作工具宣传片用重绘字卡提出问题，用原组件的任务列表展示真实状态，用裁切后的原生菜单证明分配操作，再用重新排版的结果面板与品牌收尾。若原界面整体不适合出镜，也可全部采用宣传重绘；能力依据仍来自项目，成片说明这是演示呈现。示例是选择方法，不是该功能已经实测的声明。

## 扩展成片前验证

先选能暴露接入风险的一小段，验证字体和素材、必要状态、镜头裁切、声音对齐及重渲染稳定性。原生交互重点检查操作与光标；重绘重点检查可读性、功能映射和状态编排，不要求像素还原旧 UI。已验证的同类接入可复用，不机械重复试跑。

新增模式的说明与静态检查不等于具体项目试拍成功；只按实际运行、导出、审看与听审结果报告完成范围。
