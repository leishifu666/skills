# 坤坤魔法 V5：快剪研究试剪

21 秒，1920×1080，30 fps，630 帧，H.264 + AAC 立体声

## 本版变化

- 不再把各段平均分时：输入约 2 秒，发送前推近 0.25 秒，发送后拉远 0.30 秒，作品队列移动 0.22 / 0.30 秒，结尾留约 2 秒读品牌
- 首页仍从原生动画 0 开始，按 GSAP 重新分配速度；卡片接到节点时读取原 shader 的屏幕位置、尺寸、旋转，不再用中央大图盖住首页淡出
- 输入、模型浮层、玻璃发送按钮、生成中 shader 与图片节点直接导入当前项目组件。发送帧 248 实际触发组件回调，再由演示数据切换运行状态
- 结果先在原节点出现；同一个屏幕矩形接到图片层，展开为带透视、近远速度差的作品队列，再收束到坤坤自身 Logo
- 声音改为授权音乐 + 空气转场 + UI 接触三层。输入段压低音乐，结果前安排短暂音乐空隙；音效按具体动作剪辑、调整增益和声像

## 设计依据与真实 UI

沿用用户此前确认的 [设计规范](D:/Penguin-Magic_7.0/Penguin_Magic_main/outputs/kunkun-product-video-v3/DESIGN.md) 与 [规范可视化](D:/Penguin-Magic_7.0/Penguin_Magic_main/outputs/kunkun-product-video-v3/design-review.html)。本轮新编排不改变产品组件样式、默认模型或业务行为。图群纵深与品牌遮罩是宣传镜头，不宣称是软件中存在的页面。

组件来源与 SHA256 见 `source-evidence.json`。出镜的原项目图片为历史作品 3981 与创意素材 153 / 146 / 139 / 207；其余含广告标识的图片未选用。出镜厂商 / 模型图标来自当前模型选择器。

生成结果使用现有作品，状态与输入按帧驱动；没有发起付费生图、没有写入用户数据，剪辑时长不代表生成耗时。真实发送回调仅记录事件，不连接后端。

## 时间表

| 秒 | 场景与动作 | 声音角色 |
|---|---|---|
| 0–2.625 | 原生卡片出生、展开、选取 | 音乐脉冲 + 短空气声 |
| 2.625–3.75 | 卡片落入创意模板节点，建立连接 | 卡片落点、连接接触 |
| 3.75–6.375 | 推近输入，分组打字，停留阅读 | 降低音乐，少量不等距键盘音 |
| 6.375–7.875 | 拉回参数，真实模型菜单切换 | 菜单打开、选中 |
| 7.875–8.925 | 突然推近发送，点击后快速拉远 | 短空气声、接触、反向旅行 |
| 8.925–10.125 | 原生生成状态 | 音乐先降，再短暂收掉 |
| 10.125–11.625 | 结果出现、镜头推进、同矩形交接 | 结果落点、音乐重入 |
| 11.625–14.625 | 作品纵深展开，两次快移 | 不同长度与方向的空气声 |
| 14.625–16.875 | 群像停留、收束主作品 | 音乐让位，聚拢 |
| 16.875–21 | 同一作品进入品牌形状，标题落定 | 品牌收束、音乐尾音 |

## 声音来源与边界

主音乐：[160BPM Electronic Loop / RUOK](https://opengameart.org/content/160bpm-electronic-loop)，CC0

空气声：[Air whoosh / pyranostudios](https://opengameart.org/content/air-whoosh)，CC0

操作声：[Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds)，CC0

许可页面与原包许可保留在 `audio/`，42 个音乐区段及采样事件记在 `audio-cues.json`。本次代码只剪辑、混音现成录音，没有程序生成旋律或噪声。参考片音轨未用于成片。

已完成信号和媒体验证，最终听感没有实际耳听验收；不能将“峰值不削波”“音轨能播放”当作听感合格。试听入口在 `video-review.html`。

## 实际验证

- 先渲染 3.5–13.5 秒连续 10 秒交互段，检查输入、选模型、发送回调、生成状态、结果交接与纵深展开
- 全片 630 帧逐帧渲染，运行时异常清单为空；检查关键帧、首尾、文字遮挡、卡片交接和模型浮层
- 对完整 MP4 解码、黑帧检测、音轨样本峰值及声画时长核验，机器可读结果在 `verification.json`
- 播放页面在 1440 px 和 600 px 宽度实际运行，未出现横向溢出；播放与时间跳转正常，见 `review-test.json`
- `npm run build` 通过，原有较大 chunk 等构建提示保留在 `build-validation.log`；不将构建成功当作业务后端已执行

研究范围、原片、时间码和连续帧见 [研究 HTML](D:/Penguin-Magic_7.0/Penguin_Magic_main/outputs/mg-research-v2/research-review.html) 与 [研究记录](D:/Penguin-Magic_7.0/Penguin_Magic_main/outputs/mg-research-v2/研究结论.md)。本版本是根据研究生成的试剪，不代表已经得到用户对视觉与听感的认可。

## 重渲染

在原项目根目录执行：

```powershell
node outputs/kunkun-product-video-v5/source/build.mjs
node outputs/kunkun-product-video-v5/source/capture.cjs full
python outputs/kunkun-product-video-v5/source/sound.py
ffmpeg -y -i outputs/kunkun-product-video-v5/picture.mp4 -i outputs/kunkun-product-video-v5/soundtrack.wav -map 0:v -map 1:a -t 21 -c:v copy -c:a aac -b:a 256k -movflags +faststart outputs/kunkun-product-video-v5/kunkun-product-launch-v5.mp4
node outputs/kunkun-product-video-v5/source/check-review.cjs
python outputs/kunkun-product-video-v5/source/verify.py
```

工程依赖当前项目 React / GSAP / Three / esbuild 与已有视频素材提取文件；`stage.html` 是本次包含图片和组件的离线打包产物。临时数据替换仅发生在视频 bundle 构建阶段，没有改业务文件。
