# Darwin 技能优化

审计用户指定的技能，用可观察的任务结果判断改动是否有效。保留已有改动、技能专业知识和真实操作约束，按当前授权完成优化；不默认创建分支、worktree 或 Git 提交。

## 工作方式

1. 确认目标文件、实际宿主和当前加载入口，读取相关技能及其真正依赖的资源。检查 frontmatter、触发边界、引用、重复指令、权限冲突和过时的工具用法。
2. 为发现的问题保留证据。将目标、输入输出及必要约束放在入口；仅在流程确有多个模式时将细节分到 references。简单技能保持自包含。
3. 做最小且完整的修改。删除不会改变决策的重复提醒，不用固定分数、强制反例数量或强制确认点代替判断；详细参数仅用于需要确定性或存在实际风险的步骤。
4. 运行格式和引用检查。用真实或代表性的任务检查正确触发、任务完成、资源可用性和授权边界。复杂技能在可用且已授权的环境中进行前后行为对比；对子代理给出原始任务与资源，避免泄露预期答案。
5. 只保留有证据支持的改进。失败时仅恢复本次改动，不回退用户原有工作；已有授权继续有效，只有关键输入或新增权限缺失才提问。报告改动、检查结果和剩余限制。

## 验收与可选资源

- 静态检查只能证明结构、引用等性质。没有实际任务对比时，不声称质量、速度或成功率提高，也不把自评分当作实测。
- 若用户要求复核旧版评分方法的研究依据，读取 [研究资料](references/skilllens-evidence.md)，并核验原始论文及适用条件；其中历史数字不是本次测量结果。
- 跨宿主分发时检查路径、工具和运行时要求。明确绑定单一宿主的技能应如实标注，不为了“通用”删除真实依赖。
- 只有用户需要成果卡片时才检查并使用 scripts/screenshot.mjs；普通审计以修改与验证说明交付。

用户明确要求 autoresearch、九维评分或完整多轮实验时，读取 [完整评测流程](full-evaluation.md)。这些评分和展示步骤只用于该专项模式，不能作为简单修改的通用门槛；执行前以当前授权校准其中的提交及检查点。
