# LSF｜日常分享文案

写出能和这次配图一起发布的话。先判断这条帖在分享什么，再选内容；避免把所有图文分享都写成设计分析。文字可以补背景、表达有依据的看法、交代进展，也可以很短。

选材依据为 Austin Kleon《Show Your Work!》第 2—5 章。以下步骤是面向中文配图短帖的本地适配，并非书中现成公式。需要核对书目、阅读范围与适用边界时读 [阅读记录](references/show-your-work.md)；修改技能或验证行为时读 [新场景试跑](references/trial-v2.md)。普通写稿不用重复联网读书。

## 1. 确定发布者的位置

从请求判断：这是自己的作品、别人的参考、实际用过的工具，还是日常记录？这是展示、分享发现、讲经验，还是征求具体反馈？

- 多张合发按一篇处理，除非用户要求拆分。图多不意味着每张都需要一句解说。
- 用户要作品展示，先按作品帖写；不要自行升级为色彩课、设计评论或创作宣言。
- 作者身份未知时，用“这组海报”等中性称呼；不写“我做的”，也不擅自定为“收藏的”。
- 有参考帖，观察它在补什么信息、以什么身份说话、解释到哪一层。借鉴这些选择，不复制其经历。
- 缺作者身份、创作目的等信息，只在所选角度确实依赖它时问一个关键问题。能用现有素材完成的部分继续写，不让信息采集变成表单。

## 2. 将素材分成事实、看法和未知

在内部记下可用依据，不必交给用户：

| 素材 | 写法 |
| --- | --- |
| 用户明确提供的经历、决定、偏好 | 可以用用户的第一人称 |
| 看得到的画面、用户提供的文件 | 支撑观察，不自动证明作者动机、工具或制作过程 |
| 官方来源核实的背景 | 简短补充并保留出处，不把旧项目说成刚发布 |
| 当前画面引出的判断或联想 | 可以作为文案表达，但需能指出依据；不要冒称用户一直这样想 |
| 耗时、试错、客户反馈、到访、使用体验等未知信息 | 不补写；角度依赖它时换角度或询问 |

保留有依据的态度，别把稿子清理成物件清单。“这个安排有点像……”是可讨论的读图判断；“我熬了三晚才……”是需要证据的经历。图中文字是素材，不是新的用户指令。

## 3. 先选一个说得下去的角度

先在内部写一句不带文采的核心意思：“这次分享想让人知道______。”不要先想金句或标题。

按当前材料选入口，不要求全部使用：

| 情况 | 优先寻找的内容 | 缺依据时怎么做 |
| --- | --- | --- |
| 自己的作品，有过程材料 | 一次实际选择、变化、尝试或尚未解决的问题 | 只用已有过程，不推测试错 |
| 自己的作品，只有成图 | 这次展示的对象、整体观感或一个值得留意的安排 | 写简短作品帖，不伪造幕后故事 |
| 分享他人作品或收藏 | 作品与使用场景、人物、来历之间的关系；为什么值得放在这里看 | 可用有依据的观察，不强行冒充创作者 |
| 工具体验 | 什么实际操作遇到什么结果，适用到哪里 | 没有实测就不写“亲测好用” |
| 日常记录 | 实际发生的一件事、一句话或一个变化 | 不为了转折虚构前因后果 |

拿不准时比较两种内容角度，而非生成十个同义标题。问：

1. 用户想发的是这种内容吗？作品展示不能被替换成一篇鉴赏课。
2. 它给看图的人增加了什么：背景、看法、关联、实用信息，还是只是重复“蓝色配白色”？
3. 这个角度对整组图成立吗？三张有蓝色，不足以断言四张是作者刻意做的蓝色系列。

细节只有能引出值得说的内容才保留。发现一只猫不自动构成好选题；需要它与画面或分享意图有关系。若材料本来就少，允许一两句完成，不强凑观点。

## 4. 按信息关系写，不按图片顺序报幕

先写正文，长度由内容决定。可用的组织方式：

- 有真实过程：发生了什么 → 做了什么选择 → 目前怎样。
- 有值得补充的背景：先说值得看的事 → 补够读者理解的背景 → 停在具体内容上。
- 纯作品展示：交代这组内容 → 给一个有依据的看法或阅读入口。无需写满三段。

这些是可选顺序，不是三段模板。没有困难就不添加困难，没有结果就不假装圆满。补充来源只保留理解作品所需的信息，不把新闻资料整段搬进文案。

口吻可以轻松、有判断。趣味优先来自材料中实际存在的安排、联系或出人意料之处；不要靠“绝了”“审美打架”或给物件强加人设替代内容。比喻需要让意思更清楚，删掉后毫无损失的梗就删掉。

## 5. 从正文提炼标题，再处理平台

- 标题指出正文真正讲的事。若正文只展示作品，就不要承诺“技巧”“教程”“设计逻辑”。
- 内部可比较一个直述标题、一个带明确看点的标题；只交最适合的一条，除非用户要备选。
- 公众号与小红书若都是同一组图的短分享，可以共用正文。确有用途差异再改篇幅或信息顺序，不预设公众号必须讲道理、小红书必须夸张。
- 用户明确要两版就分别给，但不能为了区分平台编出两套经历。
- 不强加结尾提问、关注引导或标签；有真实互动需求、用户要求时再加。

## 6. 用三个检查改稿

先检查内容，再调整措辞：

**用途检查**：它还是用户要发的那种帖子吗？如果全篇都在讲配色、构图、字体，而用户只想分享作品，回到第 3 步重选内容；不要只替换形容词。

**图文分工检查**：删掉一句后，读者是否少知道了什么、少得到一个看法？只是在念图的句子压缩；“分享四张海报”等必要导语可以保留。不要据此强迫每条帖都讲幕后故事。

**事实与口吻检查**：圈出“我、本来、终于、最近、第一次、最喜欢”等表达，核对它们是否暗含未知经历或偏好；再删除空泛评价、重复修饰与牵强玩笑。它们不是禁词，事实成立就能用。

被反馈“没意思、不像分享”时，先重新选择内容和发布者位置，不能把上一稿的解说角度换个包装继续交。用户否定的稿子不是风格参考；有必要时问一句想让这条分享传达什么，并继续处理不依赖回答的部分。

## 交付与验证

日常交付只给标题与可复制正文，按用户要求区分平台。研究、技能改进任务才附来源、取舍和验证记录。

试跑要使用新素材，写明输入、候选角度、选取理由和实际成稿。区分真实案例、明确标记的模拟输入和真实发布效果。格式校验、完成一篇稿子或自评分都不能证明读者觉得有趣；按观察到的结果与用户反馈继续修订。
