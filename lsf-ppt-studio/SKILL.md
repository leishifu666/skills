# LSF PPT Studio

这是唯一的 PPT 技能入口。它组合两个独立维护的能力源：Guizang 负责完整 deck、页面叙事、运行时与演讲者模式；LSF风格工厂负责视觉提取、16维风格协议、模板库与配图。

除非用户明确要求其他语言，使用中文提问、解释和报告。代码、CSS 属性、标准名称及必要术语保留原文。

## 先确认本地能力源

读取 [sources.json](sources.json)，确认其中两个 `skill_root` 和私有图片配置存在。能力源位于技能扫描目录之外，这是为了只显示本技能一个入口，并让 Guizang 保持干净 Git 仓库。

不要把私有配置、API Key、运行日志或生成图片复制进本技能。调用图片脚本时只传 `--config` 路径，不读取或输出密钥值。

## 模板优先检查点

本技能有两类现成资产：Guizang 的两套原生母版，以及 LSF 风格工厂中已经归档的主题风格库。凡是用户要生成演示稿、提示词展示页、电子杂志或社交媒体页面，并且尚未明确选定模板时，必须先读取 [模板与主题风格选择](references/template-selection.md)，并读取 `sources.json` 中风格工厂的 `styles/index.json`。在聊天中同时展示两类现成资产，等待用户选择。

硬性顺序：

1. 先展示 Guizang 原生母版及其官方主题色。
2. 紧接着展示 LSF 主题风格库中的全部现有风格；不得隐藏、截断成“等”或只挑推荐项。
3. 最后提供“创建新风格”入口，但不得让它取代现有资产。
4. 确认画布比例是原生 16:9，还是沿用所选视觉语言做竖版适配。
5. 用户确认后，才进入内容规划、模板复制或正式制作。

用户说“先让我选风格”“给我模板选择”“有哪些模板”时，默认含义是查看现有模板，不是要求生成新的自定义方向。除非用户明确要求可视化预览，否则直接在聊天中列出模板；不要自动创建 HTML 选择页。

## 路由到正确工作流

### 生成完整 PPT

用户要从主题、大纲、文档、数据、图片或截图生成正式演示稿时：

1. 读取 `sources.json` 中 Guizang 的 `SKILL.md`。
2. 如果用户尚未选定母版和主题，执行“模板优先检查点”，不得跳到自定义风格。
3. 按其需求澄清、叙事弧、页面规划、模板复制、内容填充和验证流程执行。
4. 正式演讲必须加载其 `references/presenter-mode.md`，生成稳定 `data-slide-id` 和 `SPEAKER_NOTES`。
5. 始终复制模板到目标项目后再修改。不得直接修改 Guizang 源码仓库。

### 提取、创建或管理风格

用户给出截图、HTML、URL、文字风格、色板、已有风格或 CSS/token，并希望得到 PPT 视觉系统时：

1. 读取LSF风格工厂的 `SKILL.md`。
2. 按其7类输入和16维分析流程生成风格 JSON、CSS token 和模板。
3. 风格文件、模板与生成图片写入风格工厂规定的位置或当前项目，不写入 Guizang 源码仓库。

### 内容和自定义风格同时需要

读取 [references/fusion-contract.md](references/fusion-contract.md)。先确定内容结构和演讲需求，再确定视觉风格，最后把16维风格映射到复制后的 deck 模板。

原生电子杂志或 Swiss 模式遵守 Guizang 的预设主题限制。选择LSF自定义风格时，由16维风格协议拥有视觉 token，Guizang 只拥有内容结构、翻页运行时、演讲者模式和验证契约。

用户选择 LSF 主题风格库中的现成风格，或明确选择“创建新风格”时，进入此工作流。不要把“尚未选择模板”误判成“需要创建新风格”。

### 用户要求选择模板或视觉方向

先读取 [模板与主题风格选择](references/template-selection.md) 和风格工厂 `styles/index.json`，按以下顺序处理：

1. 在聊天中展示 Guizang 的两套原生母版、适用场景和主题色编号。
2. 展示 `styles/index.json` 中 `source: leishifu` 的全部现成风格，使用稳定编号 `L1...Ln`；名称、分类和标签以索引实时内容为准，不维护另一份假索引。
3. 把“C 创建新风格”放在列表末尾。
4. 明确说明原生或现成横向模板以 16:9 为基准；用户要求 3:4、4:5 或 9:16 时，让用户在“原生 16:9”与“沿用所选视觉语言做竖版适配”之间选择。
5. 如果用户选择 Guizang 原生母版，进入 Guizang 完整 PPT 流程；选择 LSF 现成风格则进入融合流程，但直接复用其已归档的16维定义，不重新发明风格。
6. 如果用户明确选择竖版适配，保留所选资产的字体、网格、配色和组件纪律，但不要声称直接套用了横向 HTML 页面结构。
7. 只有用户选择 C、明确说“现有的都不要”，或要求真正的可视化自定义方案页时，才调用 `lsf-vibe-ui-selector`。

🔴 禁止行为：只展示 Guizang 而遗漏 LSF 风格库；只展示推荐项而隐藏其他现有风格；在未展示现有资产前直接生成 5+1 自定义方案；用自创风格名替代真实资产名；用户只要求聊天内选择时擅自生成 HTML。

## 更新 Guizang

每次执行 PPT 任务前只检查更新，不自动拉取：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/update-guizang.ps1
```

检测到更新时说明提交数量并询问用户。只有用户明确同意更新后才运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/update-guizang.ps1 -Apply
```

更新脚本只允许 fast-forward，并在源码仓库存在未提交改动时停止。更新后重新读取上游 `SKILL.md` 和新增引用，不把本技能的融合规则缝入上游仓库。

## 生成与验证底线

- 最终 deck 保持单文件 HTML；项目图片可放在同级 `images/`。
- 使用自定义风格时，先完成16维分析和用户确认，再写正式模板。
- 正式演讲运行 Guizang 的 `validate-presenter-mode.mjs` 与 `check-presenter-runtime-sync.mjs`。
- Swiss 风格额外运行 `validate-swiss-deck.mjs`。
- 所有风格再按LSF工厂的 `references/checklist.md` 做视觉检查。
- 用浏览器实测翻页、总览、图片、字体、响应式状态和演讲者模式；不能只做静态文本检查。
- 无法运行某项验证时，明确列出未验证项及原因。

## 职责边界

- Guizang 上游拥有完整 deck 流程、原生 A/B 美学、运行时、Presenter 与对应校验器。
- LSF工厂拥有16维风格协议、自研风格库、视觉提取与图片生成流程。
- 本技能只拥有路由、冲突消解、组合顺序和唯一入口，不重复维护两边的详细规则。
- 上游源码采用 AGPL-3.0。使用或分发其代码时保留来源、版权和许可证；本技能不改写或隐藏上游署名。

## Before you finish

| 检查 | 要求 |
|---|---|
| 源码仓库 | `git status --short` 保持干净，生成物没有写入源码 |
| 风格选择 | 原生 Guizang 与16维自定义模式的规则没有混用 |
| 演讲能力 | 正式演讲具有页面 ID、备注、时间规划和 Presenter 校验 |
| 凭据 | 回复、日志和交付物中没有 API Key |
| 视觉验证 | 至少打开真实页面检查一次 |
| 输出位置 | 用户交付物不写入技能目录 |
