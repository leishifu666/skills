# 双引擎融合契约

本文件只处理 Guizang 完整 deck 引擎与LSF16维风格工厂同时参与时的组合方式。单独生成原生 Guizang deck 或单独提取风格时，不需要加载本文件。

## 所有权

| 决策 | 所有者 |
|---|---|
| 受众、时长、叙事弧、页数和逐页目的 | Guizang |
| 页面布局可承载的信息量 | Guizang，随后接受风格约束 |
| 演讲备注、稳定页面 ID、计时和观众屏 | Guizang Presenter |
| 配色、字体、间距、背景、圆角、阴影和视觉气质 | LSF16维风格协议 |
| 图片语义和页面槽位 | Guizang 内容计划 |
| 图片视觉风格、滤镜和精确生成尺寸 | LSF风格工厂 |
| 翻页、导航、总览、低功耗和 Presenter 运行时 | Guizang |
| 最终验收 | 两边校验同时通过 |

## 组合顺序

0. 先执行 [模板与主题风格选择](template-selection.md)。用户选择 LSF 主题风格库中的现成风格时，直接复用其已归档的16维定义进入本流程；只有选择“创建新风格”时才重新分析和生成风格。
1. 用 Guizang 的澄清清单确认受众、时长、素材、图片、硬约束和是否正式演讲。
2. 建立叙事弧、页数计划与逐页内容表。正式演讲同时规划讲述内容、时长和转场。
3. 若用户选择 LSF 现成风格，读取对应 JSON 并确认选择；若用户选择“创建新风格”，才用LSF风格工厂选择输入方式并完成16维分析。
4. 新风格需要向用户展示分析并确认；现成风格无需重新发明。只有用户明确要求可视化自定义方向时才用 `lsf-vibe-ui-selector`；“尚未选择模板”不构成调用条件。
5. 从 Guizang 源码复制最接近内容结构的模板到项目目录，不在源码仓库编辑。
6. 仅修改复制后的模板，把16维结果映射为 CSS token、字体、间距、图片处理和装饰。
7. 保留 Guizang 的翻页与 Presenter 运行时，不用风格模板中的旧运行时覆盖它。
8. 根据页面内容确定图片语义和槽位，再按风格工厂规则计算尺寸和生成图片。
9. 运行 Presenter、runtime sync、主题校验和视觉清单，然后浏览器实测。

## 16维到 deck 的映射

| 风格维度 | 作用位置 |
|---|---|
| D1–D2 配色与强调色 | `:root` 颜色、文字角色、状态色和背景节奏 |
| D3–D6 字体与字号 | 字体加载、标题/正文角色、字重、响应式字号 |
| D7 间距密度 | slide padding、网格 gap、卡片 padding 和安全区 |
| D8 背景 | WebGL、网格、粒子、等高线或纯色皮肤 |
| D9–D10 圆角、边框和阴影 | 卡片、图片、按钮和控制组件 |
| D11 动效 | 入场参数；不得破坏 reduced-motion 与 Presenter |
| D12 图标 | 图标库、描边粗细和尺寸 |
| D13 图片处理 | 槽位比例、滤镜、圆角、裁切与出血 |
| D14 卡片 | outlined、filled、glass、elevated 或 none |
| D15 装饰 | 点阵、线条、几何元素和密度 |
| D16 气质 | 全局审美判断和页面节奏 |

## 冲突规则

- 原生 Guizang A/B 模式使用其预设主题，不接受任意视觉 token。
- LSF自定义模式允许16维 token 覆盖复制后的皮肤，但不能删除运行时、Presenter、可访问性和验证契约。
- 风格模板若自带翻页脚本，只保留视觉结构，删除重复运行时，避免双重键盘和滚轮监听。
- 自定义字体或动效不能降低投屏可读性、破坏 `prefers-reduced-motion`，或让 Presenter iframe 重新排版。
- 用户内容与视觉发生冲突时，先保证内容可读和演讲流程，再调整风格强度。

## 配图配置

图片脚本支持 `--config`。始终使用 `sources.json` 中的私有配置路径：

```powershell
python <STYLE_FACTORY_ROOT>\scripts\generate_images.py --config <PRIVATE_CONFIG> --prompt "..." --output "..." --size "1920x1080"
```

不要把私有配置复制到项目、技能、日志或交付物。API 不可用时保留高质量占位并明确说明。
